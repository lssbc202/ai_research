# Agentic RL 研究日报｜2026-10-14

**目标：通过改进 harness，产生、评价并利用有训练价值的 Agent 交互轨迹。**

本期按北京时间 **2026-10-14 00:00—24:00** 归日，边界为起点不含、终点含；以 arXiv **v1 首次提交时间**判断，不按网页更新时间。本文于 **2026-10-16** 按新主题范围回顾重写。

既有候选 **218 篇**，重筛确认 **51 篇：主线研究 41、扩展方法 9、综述 1**，均完成导读；另有 **1 篇待核、166 篇未纳入**。这是对已有候选池的重筛，不代表全网穷尽。只复用已核的 v1 HTML/LaTeX 与阅读笔记，未读 PDF、未独立复现实验；数字均为作者报告。扩展方法只证明所描述的支撑环节，不能据此宣称已改善 RL。

阅读顺序可先看总览表中的“高”，再按后面的主题结构回查相关条目。“高 / 中”表示本主题下的阅读优先级，不是论文的绝对质量排名。

这里的 **harness** 指组织模型调用、工具执行、任务状态与反馈的运行框架；**轨迹（rollout）** 是一次尝试中的状态、动作、观测和结果记录。**SFT** 通过样本模仿行为，**RL** 根据反馈更新策略；**GRPO** 比较同任务多次尝试的奖励，**在策略蒸馏（OPD）** 则在学生自己访问的状态上接受教师监督。

## 2. 领域结构与研究进展

本期材料可以放在同一条数据闭环中阅读：

- **任务与环境**：可执行任务 → 验收与复位 → 难度课程。
- **轨迹生产与利用**：分支与恢复 → 失败纠错 → 成功经验与技能。
- **反馈与奖励**：可信结果 → 过程信用 → 可学习的监督。
- **采样与训练**：接口和版本一致 → 异步更新 → 完整成本。

### 2.1 任务与环境

#### 可执行任务与验收

RL首先需要模型可以反复尝试的任务，而不是只有一段题目。一个可用任务包至少要有可恢复的初始状态、执行接口和独立完成判据；否则采到的“成功”可能只是标签错误。

[SWE-Stream](https://arxiv.org/html/2610.20193v1)解决历史任务怎样修复、验收并流式生产，且用采集轨迹验证训练效用。[SWE-Nexus](https://arxiv.org/html/2610.20038v1)从已执行测试的行为覆盖构造和组合任务，贡献在可执行任务范围，尚无训练收益实验。两者互补：前者强调生产流程，后者强调任务切分与组合，不宜按不同模型的解决率比较谁的数据更好。

[Interlock](https://arxiv.org/html/2610.19686v1)进一步处理“单项完成、整体未完成”：把证据、决策和下游效果的关系纳入生成与验收。它支持一个实际检查点：**训练样本的公开材料必须足以支持私有判据，验收不能只检查几个容易达到的局部结果。**

#### 难度与课程

更多样本不等于更多学习信号。GRPO在同任务全部成功或全部失败时缺乏相对奖励；只把任务越造越难，可能进一步增加无效采样。

[Explorer-Zero](https://arxiv.org/html/2610.19868v1)让提出者实际探索，生成可达任务和检查点，再与求解者交替训练。[WEDGE](https://arxiv.org/html/2610.19420v1)先验证当前策略的具体弱点，再改变环境因子，选择既不太易也不近乎不可能的场景。[成功前缀课程](https://arxiv.org/html/2610.19349v1)保持任务不变，改为从参考轨迹较后位置开始练习。这是三种不同控制量：**改任务、改分布、改起点**，可以组合，但需要分别验证。

[EvoProbe](https://arxiv.org/html/2610.19433v1)、[CLASHarness](https://arxiv.org/html/2610.19128v1)和[CyberArena](https://arxiv.org/html/2610.19005v1)补充可生成或动态变化的环境。它们证明了环境与验收环节的可行性，没有证明“拿来训练就会提高能力”；还要额外检查学习难度、环境成本和裁判捷径。

### 2.2 轨迹生产与利用

#### 状态保存与分支恢复

同一段文本历史不一定对应同一个环境：文件可能已经改过，页面状态可能变化，外部服务也可能更新。训练数据若要支持接管或分叉，保存提示词仍不够。

[TreeFlex](https://arxiv.org/html/2610.20334v1)把节点选择、恢复和继续执行变成策略动作，训练完整搜索；[SERO](https://arxiv.org/html/2610.19397v1)则恢复学生到达的状态，让教师真正续跑。前者学习“往哪搜索”，后者提供学生未必能自己访问的后续监督。共同前提是**恢复后的状态足以让接下来的动作真实执行**，而非把教师想象的未来接到旧日志后面。

代价同样不同：TreeFlex增加搜索轮次与时间；SERO增加恢复和教师分支开销。只比较最终成功率，会遗漏数据生产系统最需要知道的成本。

#### 失败纠错与低效片段

只留成功轨迹会扔掉失败位置和恢复信息，也可能保留成功过程中的坏动作。更合适的做法是按训练用途组织数据，而非统一分成“成功可用、失败不可用”。

[WebKD](https://arxiv.org/html/2610.19834v1)从学生首次错误后修复，并控制教师表达与学生的差距；[CAFT](https://arxiv.org/html/2610.19367v1)把局部批评原因作为可消融的监督；[DTDD](https://arxiv.org/html/2610.19302v1)决定何时让教师接管，并区分学生前缀与教师后缀损失。它们共同强调学生确实访问过的状态，区别在于修复内容、标注信息和介入时机。

[DeLoop](https://arxiv.org/html/2610.19376v1)不依赖更强教师：同动作同观测的循环作负例，随后非循环动作作正例。它证明低效片段可以支持效率学习，但不是所有重复都是错，也不能把省步骤解释成同幅提高任务成功。[ProD](https://arxiv.org/html/2610.19439v1)则需要更丰富的进展判断；检测器成本与错误都属于数据质量的一部分。

#### 技能与记忆的训练作用

技能或记忆只有进入可检验的学习过程，才与本期目标直接相关。[SkillScaffold](https://arxiv.org/html/2610.18807v1)将技能用于训练期探索，允许拒绝无益帮助，部署再去掉技能通路；这与永久依赖外部技能库的推理系统不同。

[PraxisMem](https://arxiv.org/html/2610.20022v1)和[MemDuet](https://arxiv.org/html/2610.19928v1)直接训练状态化记忆动作。前者依赖联合参考状态，后者在文档环境以终奖训练选择、验证和重写；二者说明“记忆管理”可以是策略学习对象，但没有证明相同监督在真实工具系统中容易获得。[RSE-Bench](https://arxiv.org/html/2610.19910v1)提醒另一侧：记录缺失、结果配错会污染后续学习，日志正确性应在扩大采样前验收。

### 2.3 反馈与奖励

#### 结果可信度

奖励是训练目标的实现，不是任务目标本身。若验证器读取策略自己写的“成功”，优化只会更快强化这个漏洞。[机器人语言控制审计](https://arxiv.org/html/2610.19617v1)给出了高奖励对应几何失败的具体记录；这比笼统谈奖励投机更直接地约束采样系统设计。

[形式验证Agent RL](https://arxiv.org/html/2610.19298v1)用证明义务诊断提供密集反馈，同时禁止策略改规格。[ARBITER](https://arxiv.org/html/2610.18760v1)将判错绑定到合法且可执行的反例。[PVST](https://arxiv.org/html/2610.19372v1)把运行门控裁决变成偏好训练，但也暴露了合法动作被规则误拒的问题。它们不是越严格越好，而是要求**反馈由独立规则或执行证据支撑，并检查规则是否对应真实任务意图**。

#### 过程信用

终局成功只说明整次尝试有效，不能证明每一步都应强化。本期几条路径分别处理不同信息条件：

- [C3](https://arxiv.org/html/2610.19695v1)能识别坏行为时，直接修正其正信用。
- [CCPO](https://arxiv.org/html/2610.19103v1)拥有相似经验时，利用跨轨迹上下文比较估计步骤价值。
- [ProAS](https://arxiv.org/html/2610.18683v1)拥有成功路径结构时，用参考图区分进展与漂移。
- [Tev](https://arxiv.org/html/2610.18868v1)掌握隐藏正确世界时，从可验证中间状态直接生成进度奖励。

这些方法所需的信息并不等价。坏行为定位、匹配轨迹、参考图和隐藏真值都有成本与误差；没有这些前提时，不能只把某篇的训练算子移植过来。强基线下收益缩小、个别任务退化，也说明过程反馈需要按环境验证，不能跨论文最高分排队。

[IG-OPD](https://arxiv.org/html/2610.20664v1)、[DGS-WM](https://arxiv.org/html/2610.19642v1)以及集合检索中的[CASI](https://arxiv.org/html/2610.20293v1)则从工具返回中提取更细信息。它们提示工具观测值得保留，但各自使用答案似然、后续决策支持或冻结评估器作为代理，均不等于获得了无误差的真实动作价值。

### 2.4 采样与训练

#### 接口、状态和版本一致

训练时的动作必须在部署harness中仍然可执行。[HPD](https://arxiv.org/html/2610.20261v1)显式训练运行语义；[点击决策头](https://arxiv.org/html/2610.20107v1)在新框与动作语法下重放专家轨迹；[HybridAgents](https://arxiv.org/html/2610.18861v1)保留潜在输入并核查重放概率一致。三者在不同接口上处理同一约束：**训练不能悄悄使用另一份决策上下文。**

[AdCoEvo](https://arxiv.org/html/2610.19454v1)记录延迟结算轨迹的策略版本；[RSIgen](https://arxiv.org/html/2610.18688v1)在生成器更新后刷新动作监督。对持续采样系统，这意味着轨迹至少应能追溯模型、harness、工具、环境与验证器版本；版本变化后，旧成功标签可能需要重新执行或重新评分，不能自动沿用。

#### 采样效率与完整成本

[长程Muon配方](https://arxiv.org/html/2610.20256v1)处理异步策略滞后与长短轨迹权重；[Precog-RM](https://arxiv.org/html/2610.19614v1)通过早停节省rollout，但会引入预测奖励；[结果置信度训练](https://arxiv.org/html/2610.18614v1)则检验模型能否从历史预测结局。它们分别改变更新、执行长度和控制信号，不能用一个“效率提升”概括。

[自蒸馏复测](https://arxiv.org/src/2610.19789v1)说明固定步数胜出不等于同时间预算划算。数据生产线应同时记录合格轨迹数、实际交互量、教师与评分调用、环境启动与恢复、训练计算以及最终任务效果。对早停尤其要保留完整采样对照：更少生成量若伴随错误奖励和探索收缩，可能只是把成本转成了偏差。

## 3. 总结与启示

1. **先建设可验收的数据生产线，再扩大采样。** 任务可执行、初始状态可恢复、结果独立验证、日志与标签准确绑定，是本期最直接的共同要求；原始轨迹数量不是首要指标。

2. **按用途保存轨迹，别只筛成功。** 成功轨迹可提供课程前缀和参考路径；失败轨迹可用于恢复与批评；成功中的坏动作和重复片段也能形成局部监督。它们需要不同标签与损失，不能统一当作整条正负例。

3. **harness改进能否转成训练收益，要有单独证据。** 采样环境、运行辅助和过程判分各有价值，但可运行、推理提分、SFT有效、RL有效是不同结论。先固定模型与预算，再验证数据和机制的增量。

4. **优先核实信号，谨慎增加复杂度。** 稠密奖励、教师接管、技能注入和参考图都有适用条件；本期既有有效比较，也有子域退化和预算反转。选择最简单且信号可信的基线，往往比直接叠加全部新机制更利于定位问题。

5. **持续更新应保留版本与可重放证据。** 工具或harness变化会让旧动作与标签过期。模型、环境、验证器和采样策略应与轨迹一起存档，以支持重跑、重评分和后续跨日报聚合。
