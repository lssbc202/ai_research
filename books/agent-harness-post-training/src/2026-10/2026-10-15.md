### 1. MAI-Gym：统一执行、采集与训练

**原题**：MAI-Gym: An Open All-in-One Platform for GUI Agent Evaluation and RL Training across Mobile and Computer Environments

**作者**：Tong, Panrong; Kong, Quyu; Li, Pengxiang; Xia, Tianyu; Zhou, Hanzhang; Wang, Lei; Cai, Chenglin; Li, Long; Chen, Long; Zhang, Jianan; Zeng, Zhengwen; Zhang, Xu; Zhang, Gongjie; Wang, Yue; Hoi, Steven

**机构**：Alibaba Token Hub, Alibaba Group

**时间与版本**：2026-10-15 05:06:01（北京时间首次提交）；arXiv 2610.20939v1；主线研究；[原文](https://arxiv.org/html/2610.20939v1)。

**研究问题**

移动端、桌面和网页通常各有运行脚本，环境重置与奖励检查也不统一，扩展交互训练很困难。

例如训练保留五张历史截图、评测保留十张，哪怕模型权重相同，执行的也已不是同一个 Agent。多平台脚本各自演化会把这类差异藏进评测结果。

**研究方法**

一个 rollout worker 先向环境管理器申请实例，重置任务，获取观察并执行动作，最后调用验证器。评测、数据采集和 RL 共用这条路径，只在如何消费轨迹上不同。

环境管理器封装实例分配、观察、重置、动作和评价；适配器处理手机、桌面或网页原生接口，训练后端不需要为每种环境重写交互逻辑。轨迹及奖励进入缓冲区后，供统计、SFT 或在线策略更新使用。

系统再根据诊断合成可重置应用与任务，验证成功条件，混合移动和桌面交互训练模型。这里把环境生命周期和训练回路一起标准化，减少采集脚本与部署行为漂移。

**实际贡献**

它提供贯通评测、采样和训练的工程平台，比单独的 GUI benchmark 更接近可持续供数系统。统一接口本身并非新概念，实际价值取决于适配器与验证器能否忠实保留各任务语义。

**结果与代价**

9B模型在MobileWorld为78.4%、OSWorld-Verified为76.2%；仿真票务训练到真实手机的成功率28.8%到48.1%。训练使用约512张GPU、96小时和5000项任务，最高20000并行环境，不能把它当轻量微调配方。

特定票务应用真实迁移提高 19.3 个百分点，但不能推广成所有合成 GUI 任务都能迁移。大规模训练与环境并发是效果背景，不能只引用 9B 参数量就推断容易复现。

**洞察评论**

最先值得复用的是统一执行路径、可靠重置与版本化任务实例。先在少量环境验证采样和评测一致，再增加并发；否则扩容会把坏状态和错误奖励也一起放大。

依据：[正文](https://arxiv.org/html/2610.20939v1) · [S2](https://arxiv.org/html/2610.20939v1#S2) · [S3](https://arxiv.org/html/2610.20939v1#S3) · [S4](https://arxiv.org/html/2610.20939v1#S4) · [S6](https://arxiv.org/html/2610.20939v1#S6)。

### 2. GRADS：以证据依赖图控制Agent训练数据难度

**原题**：GRADS: Graph-Regulated Agentic Data Synthesis with Controllable Difficulty

**作者**：Yang, Gaocheng; Tao, Ruijie; Ye, Kai; Zhang, Senhua; Zhu, Zhengqin; Li, Ziyang

**机构**：Johns Hopkins University; Nanjing University; Amazon

**时间与版本**：2026-10-15 11:24:42（北京时间首次提交）；arXiv 2610.21167v1；主线研究；[原文](https://arxiv.org/html/2610.21167v1)。

**研究问题**

多跳任务加更多资料，不代表答案真正依赖这些资料；看起来更长可能只是干扰。

一篇长材料可能包含很多细节，但答案只依赖其中一句；用长度控制难度会让模型学会忽略干扰，而未必练到跨证据推理。

**研究方法**

先整理并去重领域记录，按共同来源关系聚类，再提供标识符精确查找与 BM25 文本检索工具。探索过程生成证据图，节点记录可核查主张和来源指针，边表示得出结论所必需的依赖。

难度由必要推理链深度、汇合分支等结构量计算，而不是让模型给题目主观打分。上下文管理通过选取相关子图调节难度，同时保留原始证据日志供追溯。

生成问题与答案后，确定性检查引用、结构等可验证约束，再由模型分别审查来源是否支持主张、推理步骤是否必要。通过的任务用于采集并训练 4B 策略，先做 SFT，再做 GRPO。

**实际贡献**

重点在“结构化难度—来源验证—下游训练”的连接。图结构只是一种难度代理，验证器自身仍可能判断错误，不能因为每条数据附验证记录就认为它必然正确。

**结果与代价**

三领域、多个解题能力档中难度可分；SFT使带boxed终答的终止率从约6%到95%以上，工具调用/轮次减半到四分之一，RL再减少最高19.5%。终止率是输出完成格式，不是答案正确率。

完成格式、工具使用效率和答案正确率必须分开。原始模型学会按规范结束，是有效的训练现象，却不能据 95% 的终止率写成 95% 的解题成功；调用减少也要与任务效果共同评价。

**洞察评论**

可把图难度与当前策略真实成功率一起记录：前者控制生成，后者判断是否适合学习。只有新增依赖确实迫使策略获得并组合证据，增加图规模才可能变成有效课程。

依据：[正文](https://arxiv.org/html/2610.21167v1) · [S4](https://arxiv.org/html/2610.21167v1#S4) · [S5](https://arxiv.org/html/2610.21167v1#S5) · [S5.SS5](https://arxiv.org/html/2610.21167v1#S5.SS5) · [S6](https://arxiv.org/html/2610.21167v1#S6)。

### 3. ARIA：学习可验证的运行时修复

**原题**：ARIA: Runtime Inspection and Amendment for Multi-Agent Systems

**作者**：Shen, Bolin; Dong, Yushun

**机构**：Florida State University

**时间与版本**：2026-10-15 02:27:47（北京时间首次提交）；arXiv 2610.20780v1；主线研究；[原文](https://arxiv.org/html/2610.20780v1)。

**研究问题**

知道哪一步出错不等于知道如何恢复，而等任务结束再诊断又无法及时阻止错误传播。

只标注“哪个 Agent 在哪一步错了”还缺训练目标：应该改什么、改完能否继续成功，以及原本正确时是否应该保持不干预。

**研究方法**

先在固定多 Agent 系统、任务和基座模型组合中采运行轨迹，挑选能够产出可验证修复的失败。选择依据兼顾失败数量与条件修复率，避免专门挑一堆无法挽救的失败。

对错误位置提出修改，重新执行后续过程，以任务评价器确认修复成功，构成“失败前缀—干预位置—修复内容—成功续跑”的配对样本，而不是仅靠裁判口头认定修好了。

专门的修复模型依次经过结构化监督、结果偏好训练和执行奖励训练，学习何时介入及如何修改。在线干预与事后得到评测反馈的恢复分别评估，信息条件不同。

**实际贡献**

核心是把失败诊断推进到可执行修复监督，并让独立模型学习运行时干预。整体并不要求所有执行 Agent 一起更新，也不能仅因训练有三阶段就认为每阶段都有独立必要性。

**结果与代价**

Qwen2.5-7B配置中，在线总体成功率21.4%，SafeAgent为17.8%；有害干预率2.0%对13.9%。带评测反馈的事后修复成功率35.3%，不能和无反馈在线21.4%混为一个指标；执行预算也不含全部离线训练费用。

在线成功率高 3.6 个百分点，有害干预率低 11.9 点，显示“不乱改”也是重要效果。事后修复的分母是失败尝试，在线成功率的分母是全部任务，二者既信息不同、分母也不同。

**洞察评论**

采集配置应以单位执行成本产出的有效修复对来比较，而不只看哪个模型最容易失败。这类监督尤其适合当前“成功及各种轨迹”的目标，但应同时保留无需干预的对照前缀。

依据：[正文](https://arxiv.org/html/2610.20780v1) · [S2](https://arxiv.org/html/2610.20780v1#S2) · [S3.T1](https://arxiv.org/html/2610.20780v1#S3.T1) · [S3.T2](https://arxiv.org/html/2610.20780v1#S3.T2)。

### 4. AdaRSI：具身智能体的按需递归自我改进

**原题**：AdaRSI: On-Demand Recursive Self-Improvement for Embodied Agents

**作者**：Peidong Wang; Ying Chang; Zhiming Ma; Xiaocui Yang; Shi Feng; Daqi Liu; Yuzhe Yang; Xu Cao; Chuang Wang; Jian Su; Daling Wang

**机构**：Northeastern University; University of Chinese Academy of Sciences; AgiBot

**时间与版本**：2026-10-15 00:51:09（北京时间首次提交）；arXiv 2610.20474v1；主线研究；[原文](https://arxiv.org/html/2610.20474v1)。

**研究问题**

失败可能来自指令、顺序或起始状态，也可能来自执行器能力不足；不区分就训练会浪费示范和算力。

例如机器人抓取失败，可能是没有先对准物体，也可能是低层动作策略真的不会；两者都直接微调，既浪费算力，也可能把错误的调用规程固化进示范。

**研究方法**

先让冻结的编程 Agent 改工具和执行规程，用模拟器快照从同一状态重试不同指令、定位和调用顺序，优先修可以由 harness 解决的问题。开发场景用于修改，另以保留场景检查效果。

只有反复改调用仍不可靠的子步骤才进入权重训练：从失败状态拒绝采样保留成功片段，或借助模拟器特权状态写专家脚本，形成子步骤示范，再微调低层 VLA（视觉—语言—动作模型）。

新策略进入执行库，经对照验证后才推荐使用；部署时程序和策略库固定，只接收正常观察。高层编程 Agent 并未训练，低层主要是示范微调，所以不能把它称作已经实现的高层 Agent RL。

**实际贡献**

它给出“先修调用，再决定采什么数据、训练哪项能力”的具体顺序，并比较只改 harness、只训练和每步都训练。增量是改进资源分配与诊断闭环，不是新的 RL 优化器。

**结果与代价**

16 个未见组合任务上，基础成功率 4.6%、只改 harness 9.9%、完整方案 13.8%。相比每步训练的 12.6%，按需方案用 966 对 3,411 GPU 分钟、416 对 1,877 条示范；GPU 时间不含语言模型开销，每任务改进平均约 1.54 亿输入 token。

相对每步训练，按需方案的 GPU 分钟约少 71.7%，示范约少 77.8%，但最终成功率仍只有 13.8%。这些节省不包括高额语言模型调用，因而不能写成总成本下降同样比例。

**洞察评论**

对软件 Agent 可借鉴按失败原因决定是否供数，但“若干次重试没成功”还不是能力不足的严格证明。应同时记录已尝试的调用变化与状态条件，避免错误归因触发不必要训练。

依据：[正文](https://arxiv.org/html/2610.20474v1) · [正文](https://arxiv.org/abs/2610.20474v1) · [S3](https://arxiv.org/html/2610.20474v1#S3) · [S4.SS1](https://arxiv.org/html/2610.20474v1#S4.SS1) · [S4.SS3](https://arxiv.org/html/2610.20474v1#S4.SS3)。

### 5. MemComposer：用任务反馈学习记忆的选择、数量与顺序

**原题**：MemComposer: Learning to Assemble Memories for LLM Agents via Reinforcement Learning

**作者**：Xie, Yixuan; Xu, Xueqiang; Fan, Xinyi; Lyu, Xinxi; Feng, Tao; Fan, Xing; Guo, Chenlei; Hao, Jie; Wang, Shaowen; Sun, Jiashuo; Han, Jiawei

**机构**：University of Illinois Urbana-Champaign; Amazon

**时间与版本**：2026-10-15 09:47:06（北京时间首次提交）；arXiv 2610.21091v1；主线研究；[原文](https://arxiv.org/html/2610.21091v1)。

**研究问题**

单条相似性分数看不到多条记忆如何共同支持任务，也不能判断是否应少放几条。

经验之间可能重复、互补或互相冲突。逐条相似度排名既看不到组合效果，也无法回答“这次应不应该一条都不放”。

**研究方法**

先用冻结执行者采轨迹，记录结果并生成事后回顾，经一致性检查形成共享经验库。检索器为新任务返回候选，组装策略决定取哪些、取几条，以及以何种顺序放进上下文，允许空集。

固定执行者、检索器与经验库，对同一任务采不同组合并完整执行，以环境二元成功反馈训练组装策略。ExPO 沿用 GRPO 的组比较思路，优化目标来自下游任务，而不是记忆相似度或文字评价。

训练因此作用于 harness 的一个局部组件：执行模型不用同时更新，较容易看清上下文组装对结果的影响；但无法修复检索候选中完全缺失的经验。

**实际贡献**

它将可变数量和有序组合一起作为可训练决策，明确区分检索召回与最终使用。与修改模型内在推理能力不同，收益依赖当前经验库和执行器的组合。

**结果与代价**

τ²-bench三领域四次试验：4B平均pass¹为50.8%，最强基线45.0%；8B为63.5%，最强58.9%。相对各自最强基线记忆token少16.9%/4.9%；pass⁴指四次全成功，不能读成通常“至少成功一次”的pass@4。

4B 与 8B 相对各自最强基线分别提高 5.8、4.6 个百分点。记忆 token 减少属于部署输入节省；为不同组合完整执行任务的训练费用是另一笔账，不能直接相抵。

**洞察评论**

如果已有大量成功、失败和恢复经验，可以先训练“如何使用经验”，不一定先改主策略。评测时应冻结经验库并检查任务划分，防止组合器靠检索到近似答案获得看似可迁移的收益。

依据：[正文](https://arxiv.org/html/2610.21091v1) · [S3](https://arxiv.org/html/2610.21091v1#S3) · [S3.T1](https://arxiv.org/html/2610.21091v1#S3.T1) · [S4](https://arxiv.org/html/2610.21091v1#S4) · [S5.T2](https://arxiv.org/html/2610.21091v1#S5.T2)。

### 6. HP-RLVR：减少采样的信用分配折中

**原题**：Hindsight-Privileged RLVR: Single-Rollout Token Credit Without Group Sampling

**作者**：Wei Chen; Yubing Wu; Zhou Xu; Haoyue Zhang; Delu Zeng; Jiahao Wang; Junmei Yang; Pan tiewen; Jingfeng Liu; Zhiheng Zhou; Bo Li; Min Chen

**机构**：South China University of Technology; Tsinghua University; The Hong Kong University of Science and Technology; Huawei 2012 Laboratories; Shenzhen Technology University; LinkSprite

**时间与版本**：2026-10-15 01:06:59（北京时间首次提交）；arXiv 2610.20497v1；扩展方法；[原文](https://arxiv.org/html/2610.20497v1)。

**研究问题**

整次尝试有结果，具体哪步应强化仍不清楚；GRPO 的多条尝试若同奖，组内比较又可能没有信号。

组相对优化需要同题多次尝试产生奖励差异；如果采样昂贵或一组全成全败，信用信号可能很弱。问题是能否减少交互，同时保留对具体动作的训练信号。

**研究方法**

每题只采一条新轨迹，用此前已完成轨迹的平均奖励作为基线，在当前采样前固定它。这样不依赖同题额外尝试，也能得到终局奖励相对历史水平的差值。

再冻结生成这条轨迹的策略，分别在当时可见历史和加入实际后续、验证反馈的条件下重打分。两种分布差异用于给 token 分配权重；事后信息只参与训练评分，部署动作仍只能看当时历史。

最终把轨迹级奖惩与局部权重结合，不额外训练价值评论家。历史基线的标准梯度性质并不自动保证整套词元加权估计无偏，二者需要分开理解。

**实际贡献**

这是减少同题交互次数的一种折中，新增事后重评分并非没有费用。缺少完全隔离词元权重作用的对照，不能把有信号等同于学得更好。

**结果与代价**

Qwen3-8B 在 ALFWorld 同为 100 次采样训练迭代，用时 1,471 对 3,390 分钟，但最好平均成功率 62.45% 对 GRPO 65.32%。每步轨迹数 4 对 32，并非等样本或等效果提速；仅一训练种子。

100 次迭代下时间约少 56.6%，最好平均成功率却低 2.87 个百分点；每步采样量也不同。因此论文展示的是时间与效果的折中，不能称为等效果加速 2.3 倍。

**洞察评论**

若环境执行远贵于模型重评分，它值得作为节约 rollout 的候选；仍需按相同总交互预算，或达到同一目标成功率的完整费用比较。只比较训练步数会掩盖真正的成本差异。

依据：[正文](https://arxiv.org/html/2610.20497v1) · [正文](https://arxiv.org/abs/2610.20497v1) · [S3](https://arxiv.org/html/2610.20497v1#S3) · [S4.SS4](https://arxiv.org/html/2610.20497v1#S4.SS4) · [S4.T1](https://arxiv.org/html/2610.20497v1#S4.T1)。

## 2. 领域结构与研究进展

本期依次讨论：**经验生产：统一执行与任务难度 → 经验加工：可验证修复与按需训练 → 经验使用：记忆组装与低采样训练**。

### 经验生产：执行一致性与任务学习价值

MAI-Gym 解决采集、训练、评测是否运行同一个 Agent，GRADS 解决合成任务是否真的需要多条证据。前者统一执行路径，后者约束任务结构；它们是互补环节，不能用一个更大的环境平台替代任务质量检查。

当前闭环可先用少量可重置任务验证观察、动作和奖励一致，再测任务结构与策略真实成功率的关系。输出能按格式结束、工具调用减少、答案正确，是三个不同结果，不应合并成“数据质量提高”。[MAI-Gym](https://arxiv.org/html/2610.20939v1#S3) · [GRADS](https://arxiv.org/html/2610.21167v1#S4)

### 经验加工：先判断怎样修，再决定怎样学

ARIA 把失败转成可执行修复对，并训练独立干预模型；AdaRSI 先尝试改 harness，再仅为持续失败的低层子步骤采示范。二者都要求把“失败多”与“有可用训练数据”分开。

区别在于学习目标：ARIA 学习介入决策及修复内容，AdaRSI 主要微调具身执行策略，后者不是高层 Agent RL 的直接实证。对软件 Agent，能迁移的是状态重放、修复验证和按原因决定供数的顺序，尚不能照搬机器人实验的收益。[ARIA](https://arxiv.org/html/2610.20780v1#S2) · [AdaRSI](https://arxiv.org/html/2610.20474v1#S4)

### 经验使用：训练局部组件，还是减少采样

MemComposer 固定执行器，用任务反馈训练记忆组装；HP-RLVR 则减少同题采样，改用历史基线与事后评分。一个改变执行者得到什么上下文，另一个改变已有轨迹怎样形成学习信号。

两者都可能节省一种成本、增加另一种成本。少量记忆 token 不意味着训练组合器便宜，少做 rollout 也不保证达到同一成功率更省钱。必须选定比较条件：相同交互预算下的效果，或达到同一目标效果的完整费用。[MemComposer](https://arxiv.org/html/2610.21091v1#S3) · [HP-RLVR](https://arxiv.org/html/2610.20497v1#S4)

## 3. 总结与启示

- **先做小规模一致性验证，再扩容。** 可靠重置、统一执行路径和独立验收是有效采样的前提。
- **以有效修复产出衡量失败数据。** 保存失败前缀、状态、干预与成功续跑；失败数量本身不是训练价值。
- **优化哪一层要明确。** harness 组件、修复模型、低层执行器和主策略不是同一更新对象，效果及费用要分别归因。
