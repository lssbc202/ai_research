### 1. Harness Scaling：把运行框架差异纳入 RL 训练分布

> **原题**：Harness Scaling for Generalizable Agentic Reinforcement Learning\
> **作者**：Fei Bai、Huatong Song、Chuan Hao、Ran Tao、Jian Yang、Bryan Dai、Wayne Xin Zhao、Ji-Rong Wen\
> **机构**：Gaoling School of Artificial Intelligence, Renmin University of China；IQuest Research；Beihang University\
> **时间与版本**：2026-10-21 17:15:50（北京时间首次提交）；arXiv 2610.29458v1；主线研究；[原文](https://arxiv.org/html/2610.29458v1)。

**研究问题**

模型在固定框架内练熟后，换一套工具名称、上下文压缩规则或工作流程，是否仍能完成同样的任务？本文研究的是执行方式的泛化，而非增加任务类别或寻找一个最强的单一框架。

**研究方法**

把 harness 拆成五个可变部分：系统提示、工具接口、观察格式、上下文管理、工作流程。每部分设置三种实现，得到 243 种组合。例如，工具可以改用别名或不透明编号，历史可以完整保留，也可以压缩后将摘要存到文件。

训练不遍历所有组合，而用传统实验设计中的“正交设计”选出 18 种：各组件的选项、任意两组件的选项组合均衡出现。每个任务在相邻两次训练步骤中使用两套结构接近的配置，不同任务的起始配置随机选择；随后用标准 GRPO 或 PPO 更新模型权重，harness 本身不接受梯度更新。

压缩后的轨迹按实际上下文分段，但奖励归一仍以原始 rollout 为单位，各段继承同一轨迹的优势；损失只计有效模型输出 token。这避免把压缩产生的多个片段误当成多次独立试验。[方法与训练契约](https://arxiv.org/html/2610.29458v1#A3.SS1)

**实际贡献**

增量是把“框架差异”变成可控训练变量，并同时检查未见过的组件组合与外部框架迁移。正交设计、PPO 和 GRPO 都是既有方法，贡献在于它们如何组织 harness 训练，而非发明新的 RL 目标。

**结果与代价**

Qwen3-4B 的 GRPO 实验中，ClawGym-Bench 未见组合的 Pass@1 从 37.33 提高到 52.78（+15.45 个百分点），Claude Code 上从 38.96 到 45.37（+6.41）。30B-A3B 模型在原训练框架上为 59.82→59.63，在未见组合上为 48.12→58.60；改善主要体现在迁移，未明显牺牲原配置表现。[表1、表4](https://arxiv.org/html/2610.29458v1#S4)

同规模随机选 18 套配置、随机分配配置以及重复同一任务同一框架的对照都较弱，支持“有组织的差异”有用。训练均为 300 步，但相同更新次数不等于相同 token、工具调用或墙钟成本；4B/30B-A3B 分别使用 16/32 张 H20。报告的三次重复是评估运行，不能误写成三个独立训练种子。[消融与配置](https://arxiv.org/html/2610.29458v1#A3)

**洞察评论**

对当前研究最直接的启示是：采集轨迹时，应把接口版本、压缩方式和工作流一起当作训练条件记录。它补充了“训练部署要对齐”的判断——可以学习适应一组明确变化的契约，而不必永久绑定一套框架；但实验只覆盖设计的变体及两个外部框架，尚不能推出任意 harness 都可迁移。

### 2. AgenticRoboRL：把不同机器人 Harness 接入同一训练接口

> **原题**：AgenticRoboRL: Bringing Coding-Agent Post-Training to Agentic Robotics\
> **作者**：Xinxin Liu、Bingxin Xu、Wenrui Bao、Ming Li、Wentao Bao、Chen Chen、Yuzhang Shang\
> **机构**：University of Central Florida；University of Southern California；Michigan State University\
> **时间与版本**：2026-10-21 01:41:09（北京时间首次提交）；arXiv 2610.28589v1；主线研究；[原文](https://arxiv.org/html/2610.28589v1)。

**研究问题**

机器人 Agent 可以调用已有 VLA 技能，也可以生成控制代码；两类 Harness 的动作和反馈形式不同。本文研究如何保留各自执行接口，把真实交互接入共同的 SFT＋RL 流程，训练上层规划器。这里的 VLA 是把视觉与语言输入转成机器人动作的模型，本文不更新这个底层执行器。

**研究方法**

共同接口设在**每次模型调用**处：代理层记录该轮实际提示、图像、工具定义、生成 token 和采样概率。适配器再提供任务、初始状态、尝试编号、终局奖励和有效性标记，把调用对应回完整实验。训练器会核对实际提示 token；重建不一致的样本权重置零。真正的任务失败仍以零奖励训练，基础设施故障则排除，避免把服务故障当成策略失误。[方法 §3.2](https://arxiv.org/html/2610.28589v1#S3.SS2)

先用强教师的成功轨迹做 SFT。RPent 教师拥有学生部署时没有的记忆，因此要移除记忆调用，并重写、审核依赖该记忆的文字推理，保留工具参数；不能简单把教师完整记录原样塞给学生。随后固定一轮策略采集同任务、同初始状态的六次尝试，用终局成功率计算组内优势，再更新规划器；每条轨迹最多抽取 16 个响应参与训练，并按轨迹归一，避免长轨迹自动获得更大权重。[方法 §3.3](https://arxiv.org/html/2610.28589v1#S3.SS3)

输出是改进后的 Qwen3.5-9B 规划器。VLA、感知和运动控制组件保持冻结；RPent 和 CaP-X 分别收集数据、分别训练，**并不是一个 checkpoint 在两种 Harness 间直接迁移**。

**实际贡献**

贡献主要是把已有的调用记录式 Agent 训练组织成机器人适配方案，并处理教师与学生上下文不一致。SFT 后接 RL、终局奖励和组内比较都不是本文首创；有价值的是保留不同执行机制，同时明确哪些记录可以进入学习。

**结果与代价**

在 RPent 的 LIBERO-PRO 800 次评测中，9B 规划器由 18.1% 提升到 SFT 的 65.1%，再到 RL 的 71.0%；RL 相对 SFT 增加 **5.9 个百分点**，不能把全部 52.9 点提升归因于 RL。另一套 CaP-X 中，分别训练的模型为 2.7%→18.7%→28.5%。[表 1、表 3](https://arxiv.org/html/2610.28589v1#S4.T1)

RPent 的报告 checkpoint 已采集 2,304 条 RL 轨迹、执行 206 次更新；SFT 使用 40,047 个监督响应。记忆重写方案在接近更新次数时为 60.2%，仅屏蔽记忆依赖响应为 55.2%，但两者同时改变了监督内容和覆盖范围，不能单独证明重写的贡献。[表 4及附录 C](https://arxiv.org/html/2610.28589v1#S4.SS5)

测试主要验证同一批任务在新初始状态和扰动下的表现，不等于跨全新机器人任务泛化；CaP-X 还使用特权状态。论文给出轨迹和更新量，但未给足完整 GPU 时及教师数据采集成本。

**洞察评论**

对当前研究最可复用的是**训练记录契约**：实际输入、策略版本、任务归属和失败类型应一并保存。统一这层记录即可复用训练器，不必先把所有 Harness 的动作形式改成一样。另一方面，“训练后不用记忆”需要重新构造学生可获得的监督上下文，不能只删除部署时的记忆模块。

### 3. BIRD-RL：有状态数据库中的轨迹隔离与训练

> **原题**：BIRD-RL: Scaling Agentic Reinforcement Learning over Stateful Data-Centric Environments\
> **作者**：Ge Qu、Jinyang Li、Xiaohan Xu、Xiaolong Li、Bowen Qin、Nan Huo、Ziwei Tang、Chenhao Ma、Reynold Cheng\
> **机构**：The University of Hong Kong；National University of Singapore；The Chinese University of Hong Kong, Shenzhen\
> **时间与版本**：2026-10-21 16:50:39（北京时间首次提交）；arXiv 2610.29426v1；主线研究；[原文](https://arxiv.org/html/2610.29426v1)。

**研究问题**

SQL Agent 不只查询数据库，还会修改数据和表结构。训练时若每条轨迹复制一份完整数据库，I/O 开销很大；若直接复用，上一条轨迹留下的修改又会污染下一条轨迹的反馈。本文研究如何保留单条轨迹的连续状态，同时支持隔离、可复用的 RL 采样。

**研究方法**

输入是有缺陷的 SQL、问题描述和数据库。模型通过 `execute_sql` 检查或修改环境，通过 `submit_solution` 提交修复。Harness 为整条轨迹分配稳定的 `trajectory_id`，把它绑定到同一数据库副本；副本按 worker 分区，避免不同采样进程争用同一实例。

轨迹结束后副本回池，但修改过的副本只标记“待重置”，在下一条轨迹领取时才恢复。这样既保留轨迹内的操作效果，也保证新轨迹从干净状态出发；超时回收处理异常退出。[执行机制见第 4 节](https://arxiv.org/html/2610.29426v1#S4)。

训练依次进行单轮推理 SFT、多轮工具轨迹 SFT、单轮 GRPO，再在上述状态池上进行多轮 GRPO；更新 Qwen2.5-Coder 模型权重。最终阶段只按提交 SQL 的测试通过率给回报，模型需从执行反馈中学会检查、定位和修复，而非得到逐步人工奖励。

**实际贡献**

最贴近本主题的增量，是把环境生命周期从“单次工具请求”提升到“整条训练轨迹”，并接入实际 SFT＋RL。副本池和延迟重置本身是成熟工程手段；本文的价值在于将它们用于有状态 SQL 训练，并测量代价。四阶段课程的成绩提升不能全部归因于数据库池。

**结果与代价**

在 500 道 BIRD-CRITIC-SQLite 任务上，7B 模型成功率从基础模型的 **26.20% 到 44.40%**；同骨干 BIRD-FIXER 为 33.60%。14B 为 48.00%。7B 完成前三阶段为 40.60%，加入最后的交互 RL 后增加 **3.80 个百分点**；这比直接与闭源大模型比较更能说明训练增量。[表 2、表 6](https://arxiv.org/html/2610.29426v1#S5.T2)。

数据库复用实验将在线生命周期 I/O 从 2.94 TiB 降至 236 GiB，作者报告 **12.8 倍减少**；另需一次性 69 GiB 的池初始化。这个比例不是总训练加速，也不是峰值显存下降，且实验中仅 9.25% 的轨迹修改数据库。论文报告 7B、14B 的训练成本分别为 93.38、152.75 GPU 小时，硬件为 H100。[第 5.3 节、表 9](https://arxiv.org/html/2610.29426v1#S5.SS3)。

**洞察评论**

对 Agentic RL，状态隔离既影响资源成本，也影响奖励可信度：模型不能为另一条轨迹遗留的状态负责。值得复用的是“稳定轨迹身份—环境租用—脏状态恢复”这组接口契约。当前证据集中于 SQL；修改频繁或难以重置的环境，收益和实现难度都可能不同，不能照搬 12.8 倍。

### 4. Uni-Mem：同时训练记忆写入与检索策略

> **原题**：Uni-Mem: Learning a Long-Horizon Agentic Memory Manager with Unified Online Policy Optimization\
> **作者**：Zhiqian Xia、Jielong Tang、Ling-An Zeng、Shixiong Kai、Rong Yao、Hao Kong、Xiao Dong、Wei Wang、Mingxuan Yuan、Siyu Xia、Haifeng Xia\
> **机构**：Southeast University；Huawei Technologies, Noah’s Ark Lab；Sun Yat-sen University；Shandong Normal University\
> **时间与版本**：2026-10-21 20:48:10（北京时间首次提交）；arXiv 2610.29671v1；主线研究；[原文](https://arxiv.org/html/2610.29671v1)。

**研究问题**

记忆问答答错，可能因为早先没有存下事实，也可能因为事实存在却没有检索出来。若把同一个终局奖励分给整条轨迹，训练很难区分这两种失误。本文训练一个共享参数的记忆管理器，让它同时学习写入、修改、删除和多轮检索。

**研究方法**

Harness 以 Mem0／Qdrant 保存记录，但绕过 Mem0 原有的固定事实提取流程。Qwen3-4B 管理器直接调用搜索、创建、更新、删除和结束工具；执行层记录每条记忆来自哪些对话片段，以及后续被谁修改或删除。来源信息用于训练归因，不展示给管理器。输入的对话片段和问题各构成一个“事件”，一个事件可含多次工具调用。

先用教师的工具轨迹做 SFT，再交替做两类在线 RL。训练写入时，利用训练集的证据片段标注直接选取相关记忆，让冻结的问答模型作答，绕过检索策略；训练检索时，同一采样组共用一份当前策略生成的记忆库，只比较检索行为。两个阶段均更新同一个管理器，问答、裁判和嵌入模型保持冻结。[第 4 节、附录 B](https://arxiv.org/html/2610.29671v1#S4)。

事件级信用分配进一步把反馈定位到有关的写入事件，并沿更新、删除记录追踪责任。若记忆库本来缺少足够信息，就把失败检索排除出此次策略梯度，而不是给它负面训练信号；同位置事件在采样组内归一化后，其工具调用 token 共享该事件的优势值。

**实际贡献**

增量不是简单地“给记忆加 RL”，而是让存储层的来源记录和更新历史参与监督，并通过控制另一阶段的变化来减少奖励混淆。相较本文对 Mem-T 的定位，它将写入端的离线模仿与检索端 RL，改为共享管理器的交替在线优化；仍需要训练问题、答案及支持证据标注，并非从无标签使用日志中自动学会记忆。

**结果与代价**

LoCoMo 上，同一 Harness、同一 SFT 初始化的管理器为 **83.56%**；普通 GRPO 到 84.02%，完整方法到 **88.80%**，相对起点增加 **5.24 个百分点**。逐步加入事件归因、阶段解耦、更新链归因，分别达到 87.05%、88.06%、88.80%。因此可以把一部分收益与具体训练机制关联，而不只比较整套系统。[表 2、表 9](https://arxiv.org/html/2610.29671v1#S5.T2)。

在统一评测协议下重测的 Memory-R2（OSS）为 77.87%，但原论文分数为 87.10%；作者指出差异来自裁判提示，故不能混用原分数和重测分数。训练使用两个 Ascend 910B 节点，其中一个以八张 NPU 训练，另一个提供模型与存储服务，且需大量问答及裁判调用；正文未给出可直接比较的总训练费用。[附录 C.3、E.1](https://arxiv.org/html/2610.29671v1#A3.SS3)。

**洞察评论**

这项工作说明，Harness 不只是采样容器，也能提供“哪些状态由哪些动作造成”的归因信息。对于记忆、计划表或文件工作区，可以先区分“信息没被保存”和“信息没被正确使用”，再考虑训练信号。但这些证据映射不能凭空产生；迁移到缺少来源标注、持续交错读写的真实任务，还需要验证。

### 5. R2S：用接管轨迹修复教师评分

> **原题**：Capable Teacher, Myopic Scorer: Reward-Free Teacher Repair for Agentic On-Policy Distillation\
> **作者**：Shu Zhao、Tan Yu\
> **机构**：NVIDIA\
> **时间与版本**：2026-10-21 01:40:08（北京时间首次提交）；arXiv 2610.28586v1；主线研究；[原文](https://arxiv.org/html/2610.28586v1)。

**研究问题**

在线策略蒸馏（OPD）让学生自己执行任务，再由教师逐 token 提供监督。但教师“能接手做完任务”，不等于它“能对学生每一步给出有用评分”：局部合理的反复搜索，可能拖到回合耗尽。论文检验的正是执行能力与评分能力之间的差距。

**研究方法**

先让未训练的学生运行任务，在每条轨迹中找出与教师分歧最大的思考回合。Harness 将环境恢复到对应状态，教师从这里独立接管八次；经结果共识或模型裁判筛选后，保留合格组中最短的完成续写。

接着，让原教师看着这条续写，重新评价**学生原有轨迹从分歧点到结束的全部助手 token**。训练教师副本在不看续写时也输出这些分布，相当于把“看到结局后的评分”学进教师权重；教师并非简单模仿自己的成功轨迹。

最后冻结修复后的教师，继续常规 OPD 更新学生。学生仍在自己的状态分布上执行，不接收教师接管文本；环境观察不计算损失。联动发生在**状态回放、接管筛选和后缀重标**，先更新评分教师，再更新行动学生。[方法与实现](https://arxiv.org/html/2610.28586v1#S4)

**实际贡献**

可借鉴之处是把成功续写用于改善评分器，而不只作为 SFT 示范。对照实验也区分了两者：直接用接管轨迹 SFT 教师已有收益，学习“续写知情评分”还能继续提升学生表现。因此证据支持评分目标的作用，但不支持把全部收益归给该目标。[表 5](https://arxiv.org/html/2610.28586v1#S5.T5)

**结果与代价**

以 Qwen3.5-9B 教师和 4B 学生为例，R2S 相对普通 OPD，在 ALFWorld、WebShop、ScienceWorld 的成功率分别由 **65.8→81.9、34.6→55.9、34.6→47.8**，即增加 16.1、21.3、13.2 个百分点。相对“只用接管轨迹 SFT 教师”的控制组，三项再提高 5.1、9.2、6.8 个百分点。[表 2、5](https://arxiv.org/html/2610.28586v1#S5.T2)

这些收益有前置成本：每组最多挖掘 2,400 个状态、进行 **19,200 次教师接管**，另需初始学生轨迹、筛选及一轮教师微调，随后才是 150 步学生训练。主表误差条来自同一最终模型的三次解码；部分学生训练曲线另做三次训练，不等于所有配置均有三次独立训练。[设置与限制](https://arxiv.org/html/2610.28586v1#S5.SS1)

**洞察评论**

对已有失败轨迹库，值得增加“恢复后教师能否完成”与“教师原评分是否识别问题”这两个独立诊断。前者成功、后者失效时，扩大示范库未必是最直接的修复方式。

适用前提是环境可恢复、接管可验收。“无需任务奖励”也不等于无需正确性线索：主实验的 ScienceWorld 筛选使用环境完成提示，其他设置使用共识或模型裁判。当前证据限于 Qwen 系列与三个文本交互环境，尚不能证明在真实网页或昂贵工具调用中更省总成本。[附录 C 与限制](https://arxiv.org/html/2610.28586v1#A3)

### 6. DynaWeave：用动态事件生成应变轨迹

> **原题**：DynaWeave: Learning to Adapt through Dynamic Scenario Synthesis\
> **作者**：Xuan Yang、Chunxiao Liu、Hongsheng Xin、Hao Xu、Ning Miao\
> **机构**：Department of Data Science, City University of Hong Kong；Hong Kong Institute of AI for Science, City University of Hong Kong；Independent Researcher；Li Auto Inc.\
> **时间与版本**：2026-10-21 17:03:10（北京时间首次提交）；arXiv 2610.29443v1；主线研究；[原文](https://arxiv.org/html/2610.29443v1)。

**研究问题**

静态任务里，除 Agent 自己操作之外，环境很少变化；现实中房间可能被别人预订、工具可能失效、用户也可能修改要求。只模仿顺利完成的轨迹，难以学会识别旧信息失效并调整计划。

**研究方法**

输入是现有任务、可执行环境、初始状态及验收器。系统合成三类外部变化：任务要求变化、环境状态变化和外部信息变化，再用有向无环图描述先后依赖。执行引擎在特定操作后、虚拟时间到达或随机条件满足时触发事件；Agent 只能看到事件规定允许透露的信息。

验收器只修改**已经发生的事件所影响的检查项**，未触发事件和无关要求继续沿用原标准。房间不可用不意味着可以擅自改用户要求的时间；用户明确改时间才修改时间检查。接受新的验收器前，检查它在关闭事件时与原验收器一致，并能区分失效的旧解法与适应后的解法。

Qwen3.5-35B-A3B 在这些环境中采集并验证 2,095 条轨迹，再对 Qwen3.5-2B/4B/9B 做 LoRA SFT，学习观察变化后的动作；不是只生成评测环境，也没有额外 RL 阶段。[方法与训练](https://arxiv.org/html/2610.29443v1#S3)

**实际贡献**

关键是将事件触发、Agent 可见信息、实际发生记录和验收标准一起接到供数流程。训练实例因此包含“变化怎样被发现、计划如何修正”，而不只是把任务描述改写成更难的文本。

**结果与代价**

4B 模型在 CostBench 的任务完成率为 72.41%→90.81%（+18.40 个百分点），ToolMaze 扰动条件下成功率为 21.25%→25.38%（+4.13）。Gaia2 总分仅从 3.3 到 5.0，适应性和时间两项仍为零；因此不能概括成已经掌握复杂现实应变。[表1、表3](https://arxiv.org/html/2610.29443v1#S4)

相同 1,048 条训练样本下，混合三类事件比去掉其中一类表现更好，但论文缺少同预算静态轨迹 SFT 对照，无法把全部提升归因于“动态性”。训练为两轮、LoRA rank 16；任务合成、独立审查和教师采样的完整成本未量化。[事件消融](https://arxiv.org/html/2610.29443v1#S4.SS4)

**洞察评论**

值得借鉴的是供数时同时维护事件日志和验收规则：否则看似优质的失败恢复轨迹，可能只是奖励标准随意放宽。用于 Agentic RL 时，这一验证流程有价值；但本文直接证据限于 SFT，不能写成已证明动态事件能改善 RL。

### 7. BRACE：用历史交互决定下一轮训练采什么

> **原题**：Measure First, Then Allocate: Calibrated Rollout Budgets for MCP Agents in Reinforcement Learning\
> **作者**：Hieu Tran、Zonghai Yao、Sunjae Kwon、Hong Yu\
> **机构**：University of Massachusetts Amherst；University of Massachusetts Lowell\
> **时间与版本**：2026-10-21 02:15:52（北京时间首次提交）；arXiv 2610.28785v1；主线研究；[论文页面](https://arxiv.org/abs/2610.28785v1)；[本次阅读的 LaTeX](https://arxiv.org/src/2610.28785v1)。

**研究问题**

GRPO 在同一任务上采多条轨迹，靠成功与失败之间的差异产生训练信号。如果一组全部成功或全部失败，奖励对应的策略梯度为零，但工具执行费用已经发生。本文尝试在采样前识别更可能产生有效对照的任务，而不是采完才丢弃无差异轨迹。

**研究方法**

BRACE 在 MCP 交互的 rollout 调度层工作。它先用环境状态检查排除初始状态已经满足目标或有证据不可达的任务；再从历史交互库提取每个训练任务的成功与失败次数，用上限约束旧记录的影响。它估计下一组五条轨迹能否同时包含成功与失败，另外考虑同组结果相关，避免把五次相似执行当成五份独立机会。

调度器按这个估计选择下一轮要执行的任务，并保留少量均匀探索。真正用于 GRPO 更新的轨迹全部由当前策略重新生成；历史库仅帮助分配采样预算，不直接作为离策略训练样本。实验更新 Qwen3-VL 2B、4B、8B 的 rank-32 LoRA，每轮选择 256 个任务，各生成五条轨迹。

论文另有 Discord：在相同任务上配对比较 Harness 修改，并仅在胜负差异提供足够证据时接受修改。**Discord 与 BRACE 是分开验证的两条流程**，本文没有证明“先用 Discord 改框架、再用 BRACE 训练”的联合闭环；本次纳入依据是 BRACE 对交互采样与实际 RL 的连接。[LaTeX §3—§5、Algorithm 1](https://arxiv.org/src/2610.28785v1)

**实际贡献**

新增信息是把有上限的历史统计、成功率不确定性和组内相关性一起接到采样前的任务选择。优先训练有难度但并非完全失败的任务，本身是已有课程学习思想；精确配对检验也不是新的统计方法。论文还证明：在已知成功率、固定组大小和共同相关参数下，相关性修正并不会改变任务排序，因此不能把更准的估计直接等同于更好的策略更新。

**结果与代价**

在 295 个留出 AWM 任务、相同本轮 16,000 次尝试后，BRACE 的 2B／4B／8B 成功率为 12.5%／14.9%／16.5%，均匀 GRPO 为 8.9%／11.4%／13.2%，分别增加 **3.6／3.5／3.3 个百分点**；相对各规模最强对照增加 1.8／2.2／2.5 点。8B 去掉历史库后降为 12.2%，说明额外历史信息是主要收益来源之一。[主结果表、组件消融表](https://arxiv.org/src/2610.28785v1)

这不是完整成本相同的比较：一个 4B 运行读取了历史 651,804 次交互，虽然有效统计受上限约束，生成这些历史数据的成本仍然存在。每个配置只有一个训练种子，四次评测种子不能代替训练重复。最终成功率依然较低，轨迹长度和无效调用也并非全面优于其他方法。[附录 Experimental setup、Bank provenance and cost accounting](https://arxiv.org/src/2610.28785v1)

**洞察评论**

如果已经持续收集成功、失败和环境状态，历史记录可以先用于**决定下一轮值得在哪里交互**，不必全部重放进损失函数。实践中应分别记录旧库成本、新采样成本和最终收益；“非零梯度更多”只是有学习机会，不能保证学得更好。Discord 的保守筛选可作另一个设计参考，但不能据此宣称本文已经实现 Harness 与模型共同演化。

### 8. DeepEvolve：冻结历史证据后再进行参数更新

> **原题**：Evolving with Open Worlds: Towards Recursive Self-Improvement for Future Forecasting\
> **作者**：Zhipeng Chen、Yunsen Liang、Yanxi Chen、Hongkang Zhao、Lingyun Feng、Ruiyang Ren、Guoxin Chen、Jia Deng、Feng Chang、Chuan Hao、Ran Tao、Jian Yang、Ji-Rong Wen、Bryan Dai、Wayne Xin Zhao\
> **机构**：Gaoling School of Artificial Intelligence, Renmin University of China；Nanyang Technological University；IQuest Research\
> **时间与版本**：2026-10-21 22:09:57（北京时间首次提交）；arXiv 2610.29784v1；主线研究；[原文](https://arxiv.org/html/2610.29784v1)。

**研究问题**

事件发生前，Agent 可以检索信息并预测结果；结果公布后，同一个检索环境却可能直接返回答案。如果此时回放任务训练，模型容易学成“查答案”，而非利用当时的信息推理。本文中的预测是研究任务本身，并非本日报新增预测栏目。

**研究方法**

系统拆成搜索团队和预测团队。搜索团队在事件尚未揭晓时收集证据并缓存轨迹；预测团队通过本地接口读取这些已冻结材料，不再访问实时网页。事件结束后得到真实结果，用于筛选成功轨迹做 RFT（成功样本监督微调），或通过 GRPO 对预测团队做可验证奖励 RL。

训练更新预测模型的参数，不更新搜索团队。另一条独立路径从轨迹提炼外部技能，影响后续搜索；再把失败模式写成任务合成技能，指导下一轮供数。外部技能整理本身不是参数蒸馏，不能与 RL 更新混称。[执行分工与更新对象](https://arxiv.org/html/2610.29784v1#S4.SS3)

**实际贡献**

与本主题最相关的是“实时收集、冻结证据、延迟获得真值、反复训练”的接口设计，它让同一批有时效性的交互记录可以用于后训练。缓存历史信息并非新概念；这里的实际增量是把团队分工、训练权限和持续供数组成一个可运行流程。

**结果与代价**

在 Qwen3-4B-Thinking 上，RL 后选择题准确率为 54.0%→55.3%（+1.3 个百分点）；图中数值预测得分为 89.05→89.36，仅增加 0.31 分。GLM-4.7-Flash 两轮 RFT 中，训练池从 600 增至 1,000 条，Brier 分数从 0.651 经 0.636 到 0.630，越低越好。这是有限轮次的改善，不等于开放式能力持续增长已被证明。[图3、图5与正文](https://arxiv.org/html/2610.29784v1#S2.SS3)

外部技能也有成本：每条轨迹的技能提炼平均约 15 次调用、30.3 万输入输出 token，尚不含最初任务收集与交互。论文用分解实验支持不同模块有用，但未充分匹配所有路线的总预算；冻结检索能关闭一类泄漏通道，也不能单凭分数提升证明完全没有数据泄漏。[表2](https://arxiv.org/html/2610.29784v1#S2.SS5)

**洞察评论**

对需要事后验收的真实任务，这个方法比“事后重新跑一遍”更有借鉴价值：先保存决策当时实际可见的信息，再用后来获得的真值训练。需要同时保存时间戳、证据版本和执行权限；否则虽然保存了对话文本，仍可能重放出一个信息条件不同的任务。

### 9. InterWebCoder：把交互轨迹变成可执行训练反馈

> **原题**：InterWebCoder: Learning Interactive Webpage Generation from Executable Tests via Reinforcement Learning\
> **作者**：Jingyu Xiao、Dasen Dai、Yuxuan Wan、Jen-tse Huang、Yintong Huo、Hongyu Zhang、Michael R. Lyu\
> **机构**：The Chinese University of Hong Kong；Johns Hopkins University；Singapore Management University；Chongqing University\
> **时间与版本**：2026-10-21 01:53:24（北京时间首次提交）；arXiv 2610.28610v1；扩展方法；[原文](https://arxiv.org/html/2610.28610v1)。

**研究问题**

训练模型生成可交互网页，需要验证点击、输入和状态转换，而不只是截图相似。每次让 GUI Agent 操作网页来打分，既慢，也会把操作器自身的失败混入奖励。本文尝试将采集到的交互行为编译成可重复执行的测试，再用于训练。

**研究方法**

GUI Agent 先在真实网站执行任务，记录动作、截图和预期变化；随后生成独立网页及 Pytest 脚本，用稳定的元素标识把测试动作与网页组件绑定。遇到失败，先根据 DOM、动作前缀和异常判断应修网页还是修测试；规则无法归因时再用模型裁判。只有测试全部通过且平均视觉相似度达到 0.90 的样本才保留。

训练分两步。先对 Qwen3.5-9B 做全参数 SFT，并将元素测试标识对应 token 的损失权重设为普通 token 的两倍，避免关键接口在大量 HTML/CSS 中被忽略。再用 GRPO 更新 LoRA：每个输入生成 32 个网页候选，奖励各取一半测试通过率与多状态 CLIP 相似度。

**测试规格由验证器持有，生成模型只看交互原型。** 因而具体联动是“动作接口和测试绑定→可执行监督与奖励→网页生成模型更新”；这里训练的是代码生成能力，并非多轮 GUI 操作策略，作为训练反馈方法供主线研究借鉴。[方法](https://arxiv.org/html/2610.28610v1#S5)

**实际贡献**

增量主要在数据与执行契约：动作、元素标识、状态变化和测试脚本形成贯通采集、SFT 与 RL 的接口，并明确区分代码错误与测试错误。GRPO、CLIP 或加权交叉熵本身不是本文的新算法。

**结果与代价**

2,058 个采集任务中保留 1,736 份样本。相同 9B 基座在 IWR-Bench、Vision2Web 的综合分由 **24.65→48.54、35.56→48.42**，分别增加 23.89、12.86 分。但 SFT 单独训练的综合分为 22.62、34.82，均低于基座；收益来自完整训练方案，不能把通过执行验证的数据直接等同于有效 SFT 数据。[表 5](https://arxiv.org/html/2610.28610v1#S7.T5)

同一 9B 设置下，作者报告奖励计算从 GUI Agent 方案的 130.01 秒/样本降到 2.08 秒，整体时间从 392.01 降到 281.18 秒，约 **1.39 倍加速**。外部模型奖励 token 为零，不代表数据合成免费：前期仍使用 GUI Agent、代码生成与模糊失败裁判；训练使用 8 张 H100。[表 6](https://arxiv.org/html/2610.28610v1#S7.T6)

**洞察评论**

对 Agentic RL，可借鉴的是把反复出现的验证流程固化为可执行契约，并让训练显式维护契约需要的标识。这样减少的是“如何操作并检查”的重复推理，不能自动减少所有 rollout 或模型更新成本。

还需保留验收边界：代码和测试共同生成、共同修复，证明的是规定轨迹下的相互一致，未证明完整复现原网站，也未覆盖所有业务行为。论文只训练一个基座，且最终基准仍包含 GUI/模型评判；这是一套有实测收益的特定反馈方案，尚不是通用验证器替代结论。[设计边界](https://arxiv.org/html/2610.28610v1#S4.SS4)

### 10. FlashNext-RL：打通长轨迹采集与训练的数据通路

> **原题**：FlashNext-RL: A System Optimization Study for Long-Horizon Agentic RL of Qwen3.8-Flash-Next\
> **作者**：Zhewei Yao、Yuxiong He\
> **机构**：Snowflake AI Research\
> **时间与版本**：2026-10-21 07:53:09（北京时间首次提交）；arXiv 2610.28998v1；扩展方法；[原文](https://arxiv.org/html/2610.28998v1)。

**研究问题**

长程代码 Agent 的 rollout 不只是 token 列表：环境进程、路由记录、训练批次和权重同步同时占用内存。单独提高推理或训练吞吐，可能仍无法让真实 RL 循环稳定运行。

**研究方法**

系统用 prime-rl 连接 SWE 沙箱、vLLM 推理和训练器。三台推理节点维持 672 条在途 rollout；执行器把每个 token 的 MoE 专家选择一并送回，训练时重放同一选择，减少训练器与采样器对同一 token 采用不同计算路径的问题。整条轨迹最长 131,072 token，保持在同一个训练 bin 内。

调度器剔除奖励全同、没有组内优势的 rollout 组，持续采集直到约 1,024 条可训练轨迹，再分片传给训练器。数据编码、解码和缓冲改为分批流式处理；沙箱只读挂载节点本地的 harness 包，避免每个并发任务复制一份。权重逐层同步时暂停生成，其余训练和采样重叠。

更新对象是 Qwen3.8-Flash-Next 的部分模型参数，前两层等组件冻结；Muon/AdamW 是参数优化器，不是本文新提出的 RL 算法。正文未完整给出 RL 损失定义，因此这里评价的是已实测的训练接口和系统实现。[运行链路](https://arxiv.org/html/2610.28998v1#S4)

**实际贡献**

这是工程研究：给出路由数据、沙箱启动、批次生命周期和模型同步的具体内存账本，并展示这些修改如何使长轨迹 RL 实际跑通。其价值不是证明某种 harness 带来更强智能，而是解释采到的轨迹怎样在资源约束下真正成为训练批次。

**结果与代价**

20 个沙箱的小规模启动测试中，本地包挂载使启动耗时从 17.9 秒降到 4.7 秒，环境工作进程内存从约 200 GB 降到 17.6 GB。真实 SWE RL 的第 5—15 步平均每步采集 1,393 条、训练 1,026 条，迭代 22.4 分钟，其中约 5.5 分钟等待采样。[表14、表16](https://arxiv.org/html/2610.28998v1#S5)

完整系统用四台各含 8 张 B200 的节点，并非“8 张卡完成整个 RL”。论文没有报告最终任务成功率或长期收敛；不同配置下的训练吞吐比较也不能直接当作同预算的端到端加速。短程数值稳定只证明这段运行没有崩溃。[实验限制](https://arxiv.org/html/2610.28998v1#S6)

**洞察评论**

对本项目可直接借鉴的是两本账：每轮到底收了多少轨迹、其中多少真的参与更新；每条轨迹除 token 外还携带多少训练必需状态。先确认这些记录、掩码和版本能正确传递，再比较训练速度。该实现依赖具体模型与硬件，迁移时应复用测量方法，而非照搬吞吐数字。

## 二、领域结构与研究进展

本期材料可以按训练流水线理解：**运行契约 → 轨迹与反馈 → 学习对象 → 采样和训练成本**。先保证样本描述的是同一次真实执行，再讨论如何让它更有学习价值。

### 1. 运行契约

#### 状态隔离与记录一致性

模型需要为自己的动作负责，而不是为被别的进程改过的环境负责。BIRD-RL 用轨迹身份管理数据库副本；AgenticRoboRL 核对实际调用输入并区分基础设施故障和任务失败；FlashNext-RL 还保存模型实际走过的专家路由。三者处理的层级不同，却都说明：**成功标记加对话文本，往往不足以构成可用的训练记录**。

与已有数据库池、调用日志和路由重放相比，这些工作并没有重新发明每个组件。值得关注的是组件间的契约：任务与初态如何绑定、状态何时重置、哪些 token 计算损失、哪个策略生成了轨迹。状态不一致时增加训练量，可能放大错误反馈，而不是增加有效经验。

#### 框架适配与跨框架泛化

AgenticRoboRL 解决“不同框架怎样共用训练管道”，两套框架分别训练；Harness Scaling 解决“同一模型怎样适应不同框架”，训练中主动改变配置。前者统一接口并不自动产生后者的迁移能力。

对既有“训练与部署运行时要对齐”的判断，本期增加了一个条件：对齐可以面向一组明确的变化规则。先固定单一框架有利于定位错误；需要跨部署复用时，再对工具、压缩和流程作有控制的变化。Harness Scaling 的结果支持这种训练组织方式，但不能推出配置越多越好，也不能把相同更新步数视为相同完整成本。

### 2. 轨迹与反馈

#### 回放与教师监督

R2S 把同一失败状态交给教师接管，借可能的后续结果修复逐 token 监督；AgenticRoboRL 则处理教师有记忆、学生没有记忆时的示范改写。两者共同提醒：**轨迹成功不代表其中所有上下文和监督都适合学生**。

相较直接做成功轨迹 SFT，接管回放能提供“当前状态还有没有可行出路”的诊断；代价是恢复环境及多次执行教师。若状态不可重置或工具成本很高，就不能只看最终成功率提升，需把回放、筛选和重标一并核算。

#### 动态验收与历史信息

DynaWeave 让环境在执行过程中发生外部变化，验收规则随合法、实际发生的事件调整；DeepEvolve 在事后真值到来时训练，却冻结决策时可见的信息。前者避免拿旧要求评价新任务，后者避免拿未来答案训练过去的决策。

二者可以借用同一类日志结构：事件时间、可见范围、状态变化和验收版本。但它们的实证不同：DynaWeave 是应变轨迹 SFT，DeepEvolve 才包含固定证据上的 RL。不能把动态场景平台的可用性等同于 RL 有效性。

InterWebCoder 则将反复进行的网页验收固化为可执行测试，减少模型裁判开销。它与上述方法互补：测试执行可以便宜、稳定，测试本身是否完整仍需单独验证；代码和测试相互通过，未必表示满足所有原始需求。

### 3. 学习对象与信用分配

Uni-Mem 先区分“信息未保存”和“信息未取出”，再利用来源记录及修改历史分配责任。R2S 则显示，作为行动者很强的模型未必是好的评分者。二者都反对把一个最终分数无差别地分配给整条链路。

对训练设计，更有用的顺序是：先确定要更新的是执行策略、记忆管理器还是评分教师；再判断 Harness 能提供哪些责任证据；最后选择 RL 或蒸馏目标。Uni-Mem 的证据标签和 R2S 的恢复接管都需要额外资源，不是更换一个损失函数就能获得这些监督。

### 4. 采样和训练成本

BRACE 在执行前分配采样预算，减少全成功或全失败的组；FlashNext-RL 在执行后过滤无信号组，并优化数据和模型传输。二者分别针对“采什么”和“怎样把采到的东西训练起来”，可组合，但本期没有联合实验。

应分开记录三种效率：**每单位交互获得多少可训练样本、每秒完成多少更新、同等总成本得到多少任务收益**。BRACE 依赖历史库，FlashNext-RL 没有最终质量结论，BIRD-RL 的 12.8 倍只涉及 I/O。把这些指标合并成一个“训练效率提升”会掩盖不同瓶颈。

## 三、总结与启示

1. **先完善轨迹契约，再扩大采集。** 至少保存任务与初态、实际模型输入、策略版本、环境身份、状态变化和失败类型；需要压缩或路由重放时，还要保留对应的训练映射。BIRD-RL、AgenticRoboRL 和 FlashNext-RL 从不同层面支持这一点。

2. **成功与失败轨迹不必只有一种用法。** 成功示范可做 SFT；失败状态可供教师接管、修复监督；历史成功失败统计也可以只用于调度下一轮采样。按瓶颈选用途，比将所有记录直接拼进训练集更合理，但收益必须连同额外采样成本验证。

3. **把需要泛化的 Harness 差异显式放进实验。** 单框架训练、同任务多框架训练、跨框架部署应分别测量。Harness Scaling 提供了较直接的受控证据，AgenticRoboRL 的统一适配接口不能替代这一检验。

4. **本期支持的是具体机制，尚不足以证明通用自我改进。** 环境状态隔离、监督修复和记忆归因有可核查的收益；动态供数、长期开放世界训练及完整成本上的优势仍有明显证据缺口。优先复用清楚的接口与对照方法，保持对大范围能力主张的谨慎。
