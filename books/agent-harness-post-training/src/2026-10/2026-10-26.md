### 1. HaMo：通过“训练—保留—释放”协调记忆与模型

> 原题：[Harness-Model Collaboration for Long-Horizon Continual Learning](https://arxiv.org/html/2610.34724v1)\
> 作者：Zhen Bi; Zhizhi Peng; Yan Wang; Xueshu Chen; Haofei Zhang; Yaobo Zhang; Zeyu Yang; Qing Shen; Jungang Lou\
> 机构：Huzhou Normal University; Alibaba Group; Zhejiang University; Ningxia University\
> 时间与版本：v1 首次提交 2026-10-26 10:21:20（北京时间；2026-10-26 02:21:20 UTC）；本次阅读 2610.34724v1。

**研究问题**

Agent 积累了成功轨迹，既可以把它们放进外部经验库，也可以拿来训练模型。前者依赖检索，后者容易遗忘。论文研究的是这两条路径如何共同工作，而不是只让经验库越存越大。

**研究方法**

先把专家轨迹整理成“任务、初始观察、策略概要”经验卡片。通过留一检索检查每条轨迹能覆盖哪些其他任务，再用贪心选择得到较少、互补的训练锚点。这里的“覆盖”指检索关系，不代表已经证明模型掌握这些任务。

新锚点与历史轨迹回放一起进入行为克隆训练：输入包含任务、观察和检索出的策略，只监督 Agent 的动作 token。同一个 LoRA 随阶段持续更新；推理时也从任务和初始观察检索，避免训练靠额外信息、部署却拿不到。

作者提出学会后可释放外部记忆，但**所有实验都关闭释放功能**。因此本篇实际验证的是“外部记忆与持续训练并用”。

**实际贡献**

把“保存什么、训练什么、推理检索什么”连接成同一套流程，并检查跨域遗忘。检索增强、行为克隆和经验回放本身都是已有技术；值得关注的是它们在连续阶段中的配合及其局限。[方法 §3](https://arxiv.org/html/2610.34724v1#S3)

**结果与代价**

Qwen3-8B 在 ScienceWorld 的最后阶段得分为 **60.49**，四阶段平均 **52.22**，平均比 Base Harness 高 **13.88 分**。跨域训练结束后，ScienceWorld 为 **52.43**，模型单独训练对照为 **24.57**；但 ALFWorld 为 **66.79**，略低于对照的 **69.34**，并非每个任务都受益。

该对照同时去掉外部记忆与历史回放，不能把全部差距归因于记忆。每阶段训练 3 个 epoch，LoRA rank 16；同域分阶段仍覆盖全部任务类型，也缺少检索、回放和训练的完整成本账。[结果 §5](https://arxiv.org/html/2610.34724v1#S5)

**洞察评论**

对本主题最有用的是把经验库同时当作**推理支援和训练样本索引**。实践上应分别消融检索、锚点选择与回放，再判断收益来自哪里。现有结果不足以支持“模型学会后就能放心删除记忆”。

### 2. InterQ-RL：校正量化执行器与训练策略之间的偏差

> 原题：[InterQ-RL: Interaction-Aware Correction of Execution Mismatch in Quantized Agentic RL](https://arxiv.org/html/2610.35303v1)\
> 作者：Yingbo Hao; Song Liu; Guanghua Yu; Zhaojing Zhou; Jianchen Zhu; Yi Zou\
> 机构：South China University of Technology; Tencent\
> 时间与版本：v1 首次提交 2026-10-26 20:08:44（北京时间；2026-10-26 12:08:44 UTC）；本次阅读 2610.35303v1。

**研究问题**

采集轨迹的执行器使用低精度算子，训练端却按另一种数值路径计算概率，两边未必还是同一个策略。Agent 的早期工具动作一旦改变，后面到达的状态也会改变；只校正当前 token，可能漏掉这部分偏差。

**研究方法**

第一步让训练前向匹配执行器的 W8A8 线性层以及 FP8 KV cache 写入方式。KV cache 是模型保留历史注意力信息的缓存，其量化也会影响后续生成。

第二步累计此前**由策略生成的动作 token**的概率比，形成到达当前状态的前缀校正；工具返回的观察不当成模型动作。再限制权重范围，按各动作段的有效支持分配校正，接入 GRPO 更新策略。

这些权重使用已有日志概率，反向传播时按常数处理，不要求增加一次模型前向。它修正的是训练分布，不是增加新工具或新提示词。

**实际贡献**

把数值执行一致性和多轮状态分布一致性一起考虑。重要性采样不是新概念；贡献在于指出只做当前 token 或单步算子的匹配仍可能遗漏 Agent 长轨迹中的偏差。[方法 §3](https://arxiv.org/html/2610.35303v1#S3)

**结果与代价**

相同 400 步训练下，Qwen3-4B 在 ALFWorld 的成功率：BF16 **97.1%**、量化感知对照 QAT **90.4%**、InterQ **96.4%**；在 WebShop 为 **54.0% / 49.7% / 53.5%**。主要效果是接近高精度质量，不是所有环境都超越 BF16。 ALFWorld 与 WebShop 的这些主结果取最后 6 次 checkpoint 评估的均值，并非单个训练终点。

ALFWorld 成功轨迹的平均回合数由 QAT **12.72** 降为 **10.06**，但这一统计排除了失败轨迹；学习曲线面积则是 QAT **82.29**、InterQ **81.96**，不能称为全程训练更快。部分设置有独立种子复验，ScienceWorld 等尚不完整，也没有给出统一的端到端 GPU 成本优势。[表1、表2](https://arxiv.org/html/2610.35303v1#S4.T1)

**洞察评论**

当 RL 结果异常时，先排查“训练器是否忠实重放了实际执行器”，再改奖励或算法。对长期轨迹而言，日志需要记录的不只是最终文本，还包括模型版本、数值配置、动作边界和策略概率。

### 3. 细粒度信用分配何时有益、何时有害：视频编辑中的多模态 Agent RL

> 原题：[When Fine-Grained Credit Assignment Helps and Hurts: Multimodal Agentic Reinforcement Learning through Video Editing](https://arxiv.org/html/2610.35497v1)\
> 作者：Lei Zhao; Zongheng Cao; Xinyu Hu\
> 机构：University of Pennsylvania; Philo Labs\
> 时间与版本：v1 首次提交 2026-10-26 22:25:40（北京时间；2026-10-26 14:25:40 UTC）；本次阅读 2610.35497v1。

**研究问题**

完成视频剪辑，需要选素材、排序、粗剪和精剪。最终作品的分数很稀疏，给每一步额外打分似乎更容易训练，但过程评审也可能奖励无用操作。论文直接比较这几种监督方式。

**研究方法**

执行环境使用 OpenCode 和 MCP 媒体工具。图像先经注册再进入对话，保留原始生成输入并关闭自动压缩、裁剪，确保训练重放看到的像素与实际采集时一致。无法注册的图像直接拒绝，避免悄悄改变观察。

训练 Qwen3.5-9B 时比较：只用最终作品奖励的 GRPO；增加逐轮过程奖励的 GRPO；以及让学生在自己的轨迹上模仿获得参考答案或逐轮建议的教师分布。过程评审按已完成回合窗口判分，给具体动作 token 添加优势。

另设衰减过程奖励：前 20 步权重为 0.5，第 20—30 步降至零，后续只按最终作品更新。这样可以检验过程提示是否只适合作为早期辅助。

**实际贡献**

主要价值是可复查的反例与执行记录：**监督更细不自动等于训练更好**。结果与过程奖励的混合本身不是新技术，论文展示了它在长工具链任务中可能奖励错方向。[方法与接口](https://arxiv.org/html/2610.35497v1#S3.SS2)

**结果与代价**

716 条训练任务、81 条按影片隔离的验证任务上，总分由基础模型 **0.284** 提升到终局 GRPO **0.413**；固定过程奖励反而只有 **0.334**，衰减过程奖励为 **0.447**。精剪子任务从终局 GRPO **0.201** 提升到衰减版 **0.293**；这些是任务评分，不是成功率百分点。

两种在线蒸馏配置总分为 **0.277** 和 **0.044**，但它们每任务只采 1 条轨迹，GRPO 为 8 条，不能据此判定蒸馏普遍劣于 RL。所有配置训练 50 次更新；avg@4 是同一 checkpoint 的四次采样评估，**不是四个训练种子**。过程判分增加评审调用，且回顾式窗口仍可能泄漏后续信息。[表3与训练配置](https://arxiv.org/html/2610.35497v1#S5.T3)

**洞察评论**

先建立可靠的终局指标，再检查过程奖励上升是否伴随最终交付改善。若过程分上升、有效完成下降，应优先怀疑奖励代理失真，不能用“更细粒度”代替因果验证。

### 4. DynaFlow：训练主 Agent 动态组织多 Agent 工作流

> 原题：[DynaFlow: Learning Free-Form Multi-Agent Orchestration](https://arxiv.org/html/2610.34467v1)\
> 作者：Ruhao Liu; Qi Li; Shizun Wang; Xinchao Wang\
> 机构：National University of Singapore\
> 时间与版本：v1 首次提交 2026-10-26 01:38:55（北京时间；2026-10-25 17:38:55 UTC）；本次阅读 2610.34467v1。

**研究问题**

多 Agent 系统不只是分配任务，还要决定谁能看到哪些信息、如何复核、何时停止。即使子 Agent 能解题，主 Agent 也可能用错误前提诱导它们，或在汇总时丢掉正确答案。

**研究方法**

主 Agent 可以直接回答、调用工具，或生成 JavaScript 工作流。工作流明确子 Agent 的角色、依赖、并行关系和输入；执行后返回结果与执行轨迹，主 Agent 再整理答案。

教师生成正确答案且委派合法的示范，第一阶段用 **2,031 条**训练主 Agent；第二阶段再用检查错误前提、诱导式验证、信息流缺陷后留下的 **712 条**。监督对象主要是第一轮推理与工作流生成，子 Agent 保持 Qwen3.5-27B 固定。

**实际贡献**

把编排策略本身变成可训练对象，并让示范筛选关注“信息如何传递”。因此收益可以较明确地关联到主 Agent 学会组织现有能力；但这仍是首轮 SFT，不是整段交互上的 RL。[方法 §3](https://arxiv.org/html/2610.34467v1#S3)

**结果与代价**

688 道数学、科学和问答题上，在相同强制工作流模式中，未训练主 Agent 的准确率 **75.87%**，DynaFlow 为 **88.08%**，提高 **12.21 个百分点**。动态模式为 **87.94%**，接近强制模式，且 47.1% 的题直接回答；平均子 Agent 调用由 **4.16** 降至 **2.44**。

调用数减少不等于相同比例的时间或费用节省。部分其他基线没有完全匹配检索能力，AFlow 也没有针对本任务重新搜索最优工作流，因此不宜直接拿所有横向差距证明训练方法全面领先。[主结果与调用分析](https://arxiv.org/html/2610.34467v1#S5.SS4)

**洞察评论**

如果目标是让 harness 更聪明，可以先训练“是否委派、怎么传递证据”这层控制，不必一起更新所有模型。下一步实验设计应单独测工作流首轮质量与后续纠错，避免把首轮规划改善描述成完整自主协作能力。

### 5. Evolve on Graph：无需问答标注的知识图谱自演化推理

> 原题：[Evolve on Graph: Self-Evolving Knowledge Graph Reasoning without Question Annotations](https://arxiv.org/html/2610.35598v1)\
> 作者：Zongyuan Sun; Shuai Zhao; Ke Shu; Ziyue Zhu; Shangyang Wu; Yuanlin Lin; Tao Wang; Shiyue Li; Yingjun Du; Anh Tuan Luu; Haoran Luo\
> 机构：Beijing University of Posts and Telecommunications; University of Helsinki; University of Amsterdam; Nanyang Technological University\
> 时间与版本：v1 首次提交 2026-10-26 23:23:04（北京时间；2026-10-26 15:23:04 UTC）；本次阅读 2610.35598v1。

**研究问题**

Agentic RL 需要大量能核验结果的交互任务。知识图谱能执行查询，但缺少现成自然语言问答标注。随机生成一个正确答案也不够：若遗漏其他正确答案，奖励就会误罚合理解答。

**研究方法**

环境先用六类逻辑查询骨架构造任务，并实际执行查询获得**完整答案集合**；剔除无答案、答案过多等样本。出题者根据图结构和证据生成自然语言问题，解题者通过图工具探索并回答。

同一模型轮流扮演两个角色。解题者按答案 F1 与格式奖励进行 GRPO；出题者根据多次解题的表现方差获得奖励，促使它生成既非全会、也非全不会的问题，形成随能力变化的课程。

规则校验与基于证据的回答检查进一步过滤问题，但后者仍借助模型，不能等同于严格证明自然语言问题与查询完全同义。

**实际贡献**

较实在的改进是将**可执行任务生成、完整答案校验、难度反馈**接进同一训练循环。自博弈和图谱检索已有先例，论文的增量是减少对外部问答标注的依赖，并让课程随训练改变。[方法 §3](https://arxiv.org/html/2610.35598v1#S3)

**结果与代价**

Qwen2.5-7B 在 CWQ 的 F1 为 **49.27**；去掉查询执行校验为 **35.64**，去掉出题者更新为 **35.83**，去掉解题者更新为 **42.15**。这支持奖励真值和双角色训练都重要。

难度奖励并非一种曲线通吃：WebQSP 上三角形式 **63.73**，高斯形式 **62.10**。训练使用 8 张 GH200；模型还受知识图谱覆盖和六类查询模板约束，结果不能直接推广到没有可执行验证器的开放网页任务。[消融表3](https://arxiv.org/html/2610.35598v1#S4.T3)

**洞察评论**

“自动出题”最应优先保证的是答案集合和问题语义，而不是题目数量。对自己的 harness，可以先找可执行的受限任务族，把奖励可核验做扎实，再扩大生成空间。

### 6. BCMAAC：用可训练信念状态支持去中心化 LLM 协作

> 原题：[Belief-Conditioned Multi-Agent Actor Critic for Decentralized LLM Collaboration](https://arxiv.org/html/2610.35398v1)\
> 作者：Tianle Chen; Shuo Liu; Christopher Amato\
> 机构：Northeastern University\
> 时间与版本：v1 首次提交 2026-10-26 21:12:41（北京时间；2026-10-26 13:12:41 UTC）；本次阅读 2610.35398v1。

**研究问题**

协作 Agent 不一定知道伙伴已获得什么信息、任务进行到哪里。把整个聊天记录塞回模型，未必能让它持续记住关键状态。这里的“信念状态”就是对当前未完全可见情形的压缩估计，不是要求模型具有主观信念。

**研究方法**

harness 提供各 Agent 当时可见的结构化侧信息，如已取得证据、工具进度、收到的消息。递归编码器结合过去状态，输出供 Agent 决策的上下文，以及训练时预测任务状态、伙伴下一动作的辅助头。

采完轨迹后，标注规则利用完整轨迹和环境内部状态生成监督。Actor-Critic 更新 LLM 行动策略及集中式价值网络，编码器还接受状态与伙伴动作监督。部署时移除集中式 critic 与辅助头，只保留本地编码器和 actor；不能把训练期隐藏答案直接送入执行接口。

**实际贡献**

将 harness 的状态整理从固定提示模板变为联合训练的模块，并利用环境日志产生稠密监督。它仍沿用集中训练、分散执行的已有思路，增量是 LLM 协作中的状态接口及辅助目标。[机制 §4](https://arxiv.org/html/2610.35398v1#S4)

**结果与代价**

以 Qwen3-4B-Instruct-2507 为起点，Stateful Tool 成功率由普通 MAAC 的 **59.2%** 提升到 **77.5%**；Filesystem Wrangling 由 **58.9%** 到 **73.0%**。结果来自 **5 次独立训练**，每次取若干晚期评估 checkpoint 平均。

单 Agent 在文件任务已有 **66.9%**，反而高于普通多 Agent 的 **58.9%**，说明增加协作本身可能引入交接损失。额外代价包括编码器、环境状态字段和逐轮标签规则，主要实验仍是受控任务，没有证明能直接迁移到任意开放工具系统。[结果 §5与评估协议](https://arxiv.org/html/2610.35398v1#S5.SS2)

**洞察评论**

与其直接训练“更强协作”，可以先定义几个可监督状态：证据是否齐全、哪个动作已经完成、伙伴是否准备好。收益依赖这些状态在部署时可估计；训练期全知标签有帮助，但执行接口必须严格隔离。

### 7. AMIE：蒸馏可部署的记忆干预策略

> 原题：[Adaptive Memory Index Evolution for Agents](https://arxiv.org/html/2610.34977v1)\
> 作者：Yuntong Hu; Tongli Su; Yuanfu Sun; Shuo Ma; Qiaoyu Tan; Liang Zhao\
> 机构：Emory University; New York University; Meituan\
> 时间与版本：v1 首次提交 2026-10-26 15:50:16（北京时间；2026-10-26 07:50:16 UTC）；本次阅读 2610.34977v1。

**研究问题**

外部记忆越多，检索越容易反复返回“相似但无帮助”的条目。AMIE 不改变记忆正文，而是训练一个控制器，决定哪些候选记忆应暂时受到抑制。

**研究方法**

教师读取查询及原生反馈中的记忆列表，标注保留或抑制；有疑问时保留。用 902 条观察、9,020 个槽位标签训练 Qwen3-8B 的 LoRA 与十槽二分类头，共 2 个 epoch。

部署时控制器输出掩码，更新每个记忆 ID 的有界抑制值；惩罚带有衰减、饱和机制，影响**后续**检索。当前回答先封存再更新状态，避免把事后信息偷用于当前答案。

基础记忆内容和下游问答模型不更新，策略也不搜索候选池外的记忆。这是后训练优化 harness 控制器，而不是持续微调回答模型。

**实际贡献**

将昂贵教师的记忆访问判断变成可部署控制策略，并明确反馈生效的时间边界。遗忘、降权或记忆重排并非新概念；较有价值的是可复用的训练接口与跨记忆后端实验。[方法 §3](https://arxiv.org/html/2610.34977v1#S3)

**结果与代价**

在未使用其训练轨迹的 MemBench 上，Mem0 的准确率从 **79.17%** 到 **82.54%**；GroupMem 的 MemoryOS 从 **35.72%** 到 **38.27%**。但 LoCoMo 的 Mem0 F1，简单计数方案 **12.85**，高于训练控制器 **12.44**，不能称为普遍最优。

LoCoMo 同时用于策略拟合与选择，其结果不是独立泛化证明。论文报告本地策略约 87 ms 的测量，但教师端包含网络、节流和重试，硬件也不对齐，因此不据此宣称固定倍数加速。[表2与运行测量](https://arxiv.org/html/2610.34977v1#S4.T2)

**洞察评论**

值得先建立无需模型的计数、时间衰减基线，再决定是否蒸馏控制器。如果简单规则已能压制重复噪声，额外训练应证明它在新查询或新记忆系统中的增益。

### 8. LARVA：联合训练视频观察与潜在推理接口

> 原题：[Joint Latent Reasoning and Observation for Agentic Video Understanding](https://arxiv.org/html/2610.35229v1)\
> 作者：Junzhang Liu; Hao Yuan; Qi Zhang; Yiming Wu; Long Chen; Zhecan Wang\
> 机构：Hong Kong University of Science and Technology; Shanghai Artificial Intelligence Laboratory; Fudan University; The University of Hong Kong\
> 时间与版本：v1 首次提交 2026-10-26 19:18:58（北京时间；2026-10-26 11:18:58 UTC）；本次阅读 2610.35229v1。

**研究问题**

视频 Agent 通常先让观察器描述画面，再由推理模型读文本、决定下一次看哪里。文字接口方便理解，却可能丢掉视觉细节，并增加反复转述开销。LARVA 研究能否把观察和推理接口一起训练。

**研究方法**

执行器提供概览、快速浏览与聚焦工具，按不同粒度取帧。教师生成 2 万条交互轨迹，只保留最终回答正确、工具调用合法的样本，先初始化文字推理与观察模块。

之后重放教师的取帧动作，把中间文字换成潜在向量块。动作、答案的交叉熵以及观察重构、教师分布对齐目标共同训练观察器与推理器的 LoRA，使传递的信息服务下游任务。

**离散取帧动作在训练中固定为教师轨迹，不对动作选择求梯度。** 因而这是交互接口的联合蒸馏，并非完整地用 RL 学会自主探索视频。

**实际贡献**

将观察接口纳入训练回路，避免只压缩上游信息却不检查下游是否还能解题。潜在推理已有较多工作，本篇更相关的是观察器、推理器、工具访问之间的具体连接。[训练 §3.3](https://arxiv.org/html/2610.35229v1#S3.SS3)

**结果与代价**

7B 模型在 VideoHolmes 的得分由文字 CoT **39.2** 到 **44.3**；如果只把两端换成潜在表示而不联合训练，得分是 **37.4**，说明压缩本身甚至可能有害。

H200 上三项任务的平均延迟由 **48.3 秒**到 **8.2 秒**，但平均帧数也由 **112.5** 降至 **75.9**、回合数由 **4.8** 降至 **3.2**，不能把全部收益归于向量表示。系统不处理音频，依赖教师轨迹，潜在表示也更难人工检查。[消融与效率表](https://arxiv.org/html/2610.35229v1#S4.T2)

**洞察评论**

对 Agent harness，观察模块并非必须是固定文本 API；但一旦改成可训练压缩接口，就需要“相同输入预算下是否保留任务信息”的消融，并保留可审计的原始观察记录。

### 9. CaliMem：用预测误差校准数据筛选 Agent 的记忆

> 原题：[CaliMem: Search-Efficient Data Agent via Calibrated Memory](https://arxiv.org/html/2610.34500v1)\
> 作者：Hanze Li; Athan Z. Li; Feiyang Kang; Jiachen T. Wang; Yuhan Chen; Ruishan Liu; Ruoxi Jia\
> 机构：Virginia Tech; University of Southern California; Princeton University\
> 时间与版本：v1 首次提交 2026-10-26 02:55:44（北京时间；2026-10-25 18:55:44 UTC）；本次阅读 2610.34500v1。

**研究问题**

让 Agent 根据经验筛 SFT 数据很容易，但“这类数据有用”可能只是一次偶然结果。CaliMem 要求 Agent 在实验前说出预期，再用预测与实际效果的差距修正记忆。

**研究方法**

Agent 提交固定大小的数据子集，harness 执行固定训练配方并返回评估结果；每次从相同基础 checkpoint 开始，避免上轮模型状态混入本轮比较。Agent 不能改学习率等超参数，唯一主要变化是数据选择。

系统分别记录相对当前最好方案的改进与预测误差，据此保留或回退方案，并收紧经验适用条件。LLM 后训练实验每次选 1 万条数据，进行一个 epoch 的全参数 SFT，最多搜索 10 次。

**实际贡献**

纳入本主题的理由是**筛选 harness 确实驱动了下游 LLM 训练**；上游 Agent 本身只改外部记忆，不做 RL。让假设先于实验登记，有助于区分“事后解释”与能指导下一次选数的经验。[方法与训练配方](https://arxiv.org/html/2610.34500v1#A2.SS3)

**结果与代价**

用 Opus 4.8 做筛选，在 Llama-2-7B 上，固定评估套件均分从 Basic Agent **44.51** 到 CaliMem **46.07**，随机子集 **42.44**，全量训练 **45.70**；所选数据为原池约 **3.7%**。代码任务中 CaliMem **59.72** 仍低于全量 **62.03**，所以少数据并非处处更好。

每个候选都要在 A100 上重训并评估，不能仅按最终数据条数计算节省。更重要的是，表中为 **10 次搜索内固定基准上的最好分数**，协议没有把它清楚分离成完全独立、搜索后封存的最终测试；本报告把它视为搜索效果证据，不当作无偏泛化提升。[附录D表13与评估定义](https://arxiv.org/html/2610.34500v1#A4)

**洞察评论**

这类供数闭环值得借鉴，但必须区分供反馈的开发集与最后验收集。否则 Agent 可能越来越会“选到对这套题有用的数据”，而不是选出普遍更好的训练集。


## 领域结构与研究进展

本日论文可以放进一条具体链路理解：**生成可验证的任务 → 执行并记录轨迹 → 形成训练信号 → 更新模型或控制组件 → 用相同执行条件检验收益**。每一步解决的问题不同，不能把所有提升都叫作“harness 更强”。

### 1. 训练数据：任务从哪里来，哪些经验值得训练

**任务生成与答案校验。** EoG 从可执行图查询出发，先确定完整答案，再让模型出题。它优先解决奖励是否可信；代价是任务被知识图谱和查询骨架限制。它适合有可执行验证器的场景，不能直接证明开放网页自生成题同样可靠。

**经验保存与训练选择。** HaMo 保留外部记忆，同时从检索覆盖关系中选训练锚点，并回放历史轨迹。它解决的是已有经验如何同时支援推理与参数更新。与 EoG 相比，它不负责自动生产新任务真值；两个机制处于数据链路的不同位置。

**选数结果的验证。** CaliMem 把数据子集交给固定 SFT 训练器，再用结果校准经验。比“凭模型判断挑好数据”多了实际训练反馈，但循环评估也引入选优偏差。记录每次子集、训练配置、开发集成绩和最后独立验收结果，才有可能判断供数机制是否真实改进。

### 2. 训练执行：采来的轨迹，是否就是训练器理解的轨迹

InterQ-RL 处理数值层面：量化算子及 KV cache 会改变动作概率，早期动作变化又会改变之后到达的状态。视频编辑研究处理观察层面：图片被 harness 重排、压缩或遗失后，训练器可能优化一个从未实际执行过的输入。

两者共同说明，**训练正确性的前提是重放契约**。最基本的记录应包括模型与工具版本、执行输入、动作和环境返回的边界、终止原因，以及必要的图像/状态引用。这不是新增一种学习算法，却直接决定奖励和梯度是否对应同一次真实交互。

### 3. 控制策略：训练主模型，还是训练 harness 的一部分

**编排控制。** DynaFlow 用筛选过的工作流示范训练主 Agent，子 Agent 固定，适合先改善委派和信息传递；但首轮 SFT 不足以证明多轮纠错也被学会。

**状态控制。** BCMAAC 联合训练状态编码器与多 Agent 策略，利用轨迹和环境内部状态产生辅助标签。比纯文本工作流更深入地改变决策输入，但要求能定义可信状态字段，且训练期隐藏信息不能泄漏到执行期。

**记忆与观察控制。** AMIE 只训练记忆抑制器，LARVA 则联合训练观察—推理的潜在接口。前者改动范围小、容易和简单规则比较；后者信息交换更紧密，可能降低开销，但更难检查中间表示。

这些方法没有共同的单一最优架构。选择取决于瓶颈：如果错误发生在委派，训练编排；如果发生在状态丢失，训练状态表示；如果只是重复记忆干扰，先试简单降权规则。不能仅因系统有多个 Agent 就默认需要同时训练所有角色。

### 4. 信用分配：正确结果，不等于正确归因

视频编辑研究显示，固定逐轮奖励可能压低最终作品分数；HaMo 的“去记忆”对照同时去掉历史回放，也无法把提升单独归因于记忆。前者是训练信号是否指向真正进展的问题，后者是实验是否隔离了改动来源的问题。

因此，收集轨迹不应只保存赢家。应保留失败、冗余操作、真实终止原因与成本；对高价值控制点，在条件允许时再采同状态的替代行动。对照实验则一次只改变一个机制，避免同时改记忆、数据和训练预算后，把所有提升归给某个组件。

## 总结与启示

**先把日志做成可训练记录。** 保存可重放的观察、动作边界、策略版本和终局判定，比先加入更多反思文字更基础。InterQ 与视频编辑工作的证据都指向这一点。

**把训练对象写清楚。** HaMo 更新模型适配器，DynaFlow 更新编排器，BCMAAC 同时更新策略与状态编码器，AMIE 更新记忆控制器，CaliMem 更新的是下游被供数模型。它们都是联动，但解决的瓶颈不同。

**正结果要有对应的代价与反例。** HaMo 并非各环境都赢；简单计数有时超过 AMIE；过程奖励和蒸馏也有负结果。阅读这些限制比只记住最好分数更有助于做工程选择。

**对自己的 Agentic RL 实验，先建立一个小而闭合的验证回路。** 固定任务和执行版本，明确一个待改控制点，收集成功与失败轨迹，必要时做同状态分支比较，再在独立验收集上同时看质量、动作成本和稳定性。当前证据支持这种逐项验证，不支持把所有自演化机制一起叠加后归功于“整体智能提高”。
