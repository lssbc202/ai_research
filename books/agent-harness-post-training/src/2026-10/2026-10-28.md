### EnvSched：基于执行环境的 RL 任务调度

> **原题**：[EnvSched: Environment-Aware Scheduling for Rollout-Efficient Agent Reinforcement Learning](https://arxiv.org/html/2610.37609v1)\
> **作者**：Sihan Yang；Weichen Bai；Ruichuan An；Yiming Cheng；Zhiyuan Feng；Tianyi Jiang；Renye Yan；Ning Ding；Yifan Zhang；Renrui Zhang；Yehui Tang；Wentao Zhang\
> **机构**：PKU；XJTU；THU；Samsung Research；CASIA；CUHK（按本文署名缩写）\
> **时间与版本**：v1 首次提交于 2026-10-28 01:38:52（北京时间）；本次阅读 v1 HTML。

**研究问题**

Agent RL 的成本常常花在执行工具、推进环境和验证结果上。只按问题文本挑选任务，可能反复抽到相似工具与状态；只挑最难任务，又可能得到全失败的一组轨迹，无法形成有效的组内学习信号。EnvSched 研究如何在相同 rollout 数量下，兼顾可学习性与环境覆盖。

**研究方法**

调度单位是“环境—任务对”：环境包含工具、状态转移和验收器，任务给出请求与初始状态。训练前，LLM 从这些材料提取操作依赖，再构建两种相似关系：同环境内保留具体工具、状态与验收信息，跨环境则抽象为查询、资格检查、关系更新等执行结构。训练中，相似任务共享历史奖励统计，估计下一次采样能否得到有差异的奖励。

每批选 64 个任务，每题生成 8 条轨迹；一半名额优先补足尚少见的环境，另一半优先选择预期有学习信号的任务，再用配额和相似度惩罚限制集中。轨迹进入 GRPO 更新 Qwen3 策略；损失只覆盖模型生成的推理和动作 token，工具返回等内容被屏蔽。新的执行结果回流到调度器，形成下一批选择依据。

系统还通过固定动作回放检查可疑的标识符捷径，并暂时限制缺少进展的任务。这里主要更新的是执行模型，调度器利用历史统计与规则调整采样；不是额外训练一个 LLM 调度策略，也不需要为估计难度再生成一批探测轨迹。[方法 §2](https://arxiv.org/html/2610.37609v1#S2)、[训练 §3.1](https://arxiv.org/html/2610.37609v1#S3.SS1)、[筛选附录 C](https://arxiv.org/html/2610.37609v1#A3)

**实际贡献**

奖励方差选题、课程学习、邻居传播都已有基础。本文的增量是将具体执行环境纳入采样单位，用环境内部关系和跨环境操作关系共同传播统计，并在真实 Agent RL 中拆开比较“只追求奖励差异”与“只追求覆盖”。这直接连接 harness 的环境描述、执行记录和训练任务调度。

**结果与代价**

在同一 EnvScaler 任务池、同批量、同 rollout 数和 200 步 GRPO 下，Qwen3-4B 相对随机调度：BFCL-v3 从 **28.83 到 31.88**，τ-Bench 从 **37.78 到 41.01**，ACEBench-Agent 从 **56.00 到 58.00**，分别增加 3.05、3.23、2.00 点。论文报告三随机种子聚合结果，另外三个模型规模的整体分数也改善；个别子项和更长训练并不总是更好。[主结果 §3.2](https://arxiv.org/html/2610.37609v1#S3.SS2)

只追求高方差会减少环境覆盖，只追求覆盖则降低奖励差异，两者单独使用均弱于组合。在线调度平均每步 34.93 秒，约占其 4B/H100 实验步时的 **2.3%**。这不等于零成本：离线 LLM 结构提取、可疑动作回放仍需资源；目前主要验证在 **51 个环境、2,550 个任务**的单一训练池，尚不能直接外推到动态新增工具或百万任务池。[消融与成本](https://arxiv.org/html/2610.37609v1#S3.SS3)

**洞察评论**

对现有轨迹系统，最容易借鉴的是让每条记录附带环境版本、工具与验收器结构，而不只保存题目和成功率。这样可以同时判断“这个任务还能提供梯度差异吗”和“模型是否一直只见到少数执行模式”。

奖励方差只是学习价值的代理：噪声验收器也能制造方差。本文加入回放筛选是有意义的，但还不能证明所有高方差任务都值得多采；迁移时应把奖励可靠性与任务覆盖一起监测。

### SynthAPI：可控环境合成与 SFT 数据配比

> **原题**：[Scaling Laws for Tool-Use Agents via Controllable Environment Synthesis](https://arxiv.org/html/2610.37648v1)\
> **作者**：Andrew Szot；Samira Abnar；Omar Attia；Abbas Kazerouni；Michael Kirchhof；Cheng-Yu Hsieh；Raviteja Vemulapalli；Alexander Toshev\
> **机构**：Apple\
> **时间与版本**：v1 首次提交于 2026-10-28 01:56:46（北京时间）；本次阅读 v1 HTML。

**研究问题**

准备更多 Agent 训练数据时，预算应花在新增工具、给已有工具增加任务，还是改变同一任务的初始数据库？这些选择都会增加样本，却不一定带来相同的泛化收益。SynthAPI 将它们拆成可独立调整的生成维度，研究环境构成怎样影响后训练。

**研究方法**

构建模型先生成应用的 Python 数据结构与 API，再生成任务指令、初始数据库、验收函数和参考求解程序。只保留初始状态未过关、参考程序执行后能过关的任务。Agent 在持久 Python 会话中调用工具，通过列应用、列工具和查文档三个元工具发现接口，主动调用 `complete_task` 才触发终局验收；工具输出、格式错误和执行异常都作为后续观察返回。[环境与接口 §3](https://arxiv.org/html/2610.37648v1#S3)、[附录 A.3](https://arxiv.org/html/2610.37648v1#A1.SS3)

GLM-5.2 用同一接口尝试每个任务至多四次，保留第一次通过验收的轨迹；Qwen3.5 学生用这些轨迹做 SFT，只对教师的推理与动作计算交叉熵，屏蔽工具观察和环境提示。参考求解程序能看到完整数据库，但用于可解性检查，不直接作为学生模仿轨迹。**本文的后训练实证是 SFT，没有开展所讨论的 RL 扩展。**

数据构成由四项控制：应用数量、每个应用的任务数量、同一指令的初始数据库数量、每份数据库的干扰数据量。作者训练 849 个不同配置的学生模型，比较相同任务数量下的分配，再拟合数据构成与下游表现的关系；这些运行用于比较配比，不是 849 次独立复现。[训练与实验 §4.1](https://arxiv.org/html/2610.37648v1#S4.SS1)、[附录 B](https://arxiv.org/html/2610.37648v1#A2)

**实际贡献**

可执行 API 环境、教师轨迹蒸馏和成功筛选已有先例。新增信息主要来自对工具多样性、初始状态变化与任务数量的系统拆分：预算很小时集中练习少量工具较有效，预算扩大后，更丰富的应用和数据库状态更有价值。这个结论是指定环境和模型上的经验结果，并不是“工具越多始终越好”。[配比分析 §4.2](https://arxiv.org/html/2610.37648v1#S4.SS2)

**结果与代价**

在相同 **32,768 个任务实例**下，4B 模型从“32 应用、每应用 1,024 指令、每指令 1 个数据库”，换成“64 应用、每应用 128 指令、每指令 4 个数据库”，并增加干扰数据：AppWorld Test-C 从 **38.4% 到 45.0%**，BFCL 从 **44.9% 到 48.8%**。这是数据配比组合的作用，不能独自归因于某一个维度；等任务数也不保证等 token、等合成成本。[表 1 与 §4.4](https://arxiv.org/html/2610.37648v1#S4.SS4)

加入构成变量后，对留出的高算力运行，归一化分数拟合误差由 0.1706 降至 0.0285。但诊断主要基于 AppWorld 与同管线生成的留出环境，且分数依赖该实验群体中的观测最高成绩；这不是任意新领域上的绝对成功率规律。单应用、确定性环境与无须用户澄清的任务，也限制了适用范围。[§4.3](https://arxiv.org/html/2610.37648v1#S4.SS3)

完整语料约 59 亿 token，其中约 7.21 亿是受监督的推理与动作；多数训练使用一台 8×B200 节点，大规模版本增加节点和训练轮次，还另有 Gemini 环境构建与教师尝试成本。与其他环境生成方法的结果比较混合了更大语料、SFT/RL 配方和不同训练预算，论文也明确不能据此隔离生成方法的优劣。[成本配置附录 B](https://arxiv.org/html/2610.37648v1#A2)、[跨方法比较 §4.4](https://arxiv.org/html/2610.37648v1#S4.SS4)

**洞察评论**

对 Harness 供数，值得保存的不只是“成功轨迹条数”，还包括覆盖了多少工具族、同一目标出现过多少初始状态、干扰信息是否足够复杂。先在固定任务和 token 预算下比较这些分配，比直接扩大生成量更能解释训练为何改善。

验证仍是边界：参考程序能够过关，仅能说明任务在生成的规则下可解，不能独立证明验收器完整表达了用户意图；四次均失败的任务被排除，也会让语料偏向教师可解的区域。若用于 RL，需要另测奖励可利用漏洞和训练中持续变化的策略分布，不能直接套用这里的 SFT 配比结论。

### PerceptRL：视觉工具轨迹的坐标纠错与过程奖励

> **原题**：[PerceptRL: Making Visual Perception Rewardable in MLLMs from Answers to Interactions](https://arxiv.org/html/2610.37471v1)\
> **作者**：Tongkun Guan、Zhibo Yang、Mingkun Yang、Haocheng Wang、Wei Shen、Xiaokang Yang\
> **机构**：MoE Key Laboratory of Artificial Intelligence, AI Institute, School of Computer Science, Shanghai Jiao Tong University；Qwen\
> **时间与版本**：v1 首次提交于 2026-10-28 00:04:10（北京时间）；本次阅读 v1 HTML，主线研究。

**研究问题**

视觉 Agent 即使会调用裁剪、标注工具，也可能把坐标放错。错误的裁剪结果进入上下文后，后续观察和计数会继续偏离目标。只看最终答对与否，无法分辨哪一次空间操作出了问题。

**研究方法**

首先从基础模型的视觉描述中挖掘错误，经两个视觉模型交叉核验、问题构造与人工审查，得到答案可精确匹配的感知题。Qwen3.6-Flash 35A3 先做混合冷启动 SFT，再进行单轮 DAPO 强化学习；随后从同一题池选出该阶段仍较难的题，用 Python 沙箱开展多轮视觉检查。DAPO 在这里是一种按组内奖励差异更新策略的 RL 方法。[§III-A–B](https://arxiv.org/html/2610.37471v1#S3.SS1)

与 harness 联动最直接的是冷启动轨迹：系统读取代码中的目标与预测坐标，调用视觉裁判或定位模型修正坐标，**重新执行修正后的代码，再把真实的新观察接到下一轮**。这称为 Coordinate Injection（CI，坐标注入）。轨迹同时保留 `#target` 声明，把每个框或点与所指对象绑定，作为 SFT 的操作示范与后续奖励接口。[§III-C.1](https://arxiv.org/html/2610.37471v1#S3.SS3.SSS1)

正式多轮 RL 使用模型自己生成的代码和坐标，奖励器将各轮框、点画在原图上，合成一张图交给裁判统一打分。每轮取其中最差操作的定位分，结合格式、重复调用、运行错误与修复信号形成过程奖励；最终答案奖励作用于整条生成轨迹，局部分只归给对应轮的生成 token。更新对象是执行视觉检查的模型，而不是外部定位器；CI 构造好的轨迹仅用于前面的 SFT，不能当作 RL 时的监督答案。[§III-C.2–3](https://arxiv.org/html/2610.37471v1#S3.SS3.SSS2)

**实际贡献**

具体增量是把工具操作的目标、坐标、实际观察与训练信用连接起来。坐标纠错避免采集阶段把错误观察一路传播，结构化声明则让训练器能定位到某一轮的空间错误。SFT、DAPO、视觉工具与过程奖励本身均已有基础，论文的价值在于它们围绕这一执行问题形成了可检查的训练流程。

**结果与代价**

在同样的 Python 工具、最多 64 轮与 128K token 上限下，七项基准平均准确率由基础模型的 **55.9% 提高到 71.6%**。这是整套 SFT、单轮 RL、多轮 RL 的合计增益，不能全部归因于坐标纠错或过程奖励。[表 II、§IV](https://arxiv.org/html/2610.37471v1#S4)

较直接的奖励消融保持相同初始化、工具与优化器：相对只用答案奖励，加入过程奖励后，RealWorldQA、BLINK、TreeBench、RealWorldCounting 分别提高 **2.0、3.0、5.1、8.4 个百分点**；第 200 步的定位忠实度为 **0.81 对 0.63**。但 CI 的单独效果主要用冻结 Gemini 的推理期纠错实验说明，并没有单独隔离“CI 冷启动数据”对后训练增益的完整贡献。[§V-C–D、表 V–VIII](https://arxiv.org/html/2610.37471v1#S5.SS3)

训练使用 64 张 A100 80GB；冷启动含 57,678 条样本，19,810 道多轮题是 36,445 道单轮题的子集，不能相加当作独立题量。多轮过程奖励仍需要视觉裁判，构造阶段还需要交叉核验与人工检查；正文没有给出完整 GPU 小时或端到端费用。结果来自一个主干，未报告训练种子方差。[§IV-A](https://arxiv.org/html/2610.37471v1#S4.SS1)

**洞察评论**

对轨迹系统，值得迁移的是“动作声明—真实执行—可定位反馈”的接口：训练器要能知道模型打算操作什么、实际操作了哪里，以及下一步看到了什么。只保存工具调用文本，难以核查这条链。

同时，定位分高不等于该操作对任务有用，模型裁判也不等于客观真值。复用时还需检验目标声明与实际代码是否一致、奖励器是否可靠，以及过程分是否改善真实任务；本文的结果支持这组视觉任务中的训练收益，尚不支持通用 Agent 都应采用同一种过程奖励。

### TeamGym：分布式信息与可训练的发言调度

> **原题**：[TeamGym: A Gym for Team Decision-Making by AI Agents with Distributed Information](https://arxiv.org/html/2610.37571v1)\
> **作者**：Chanwoo Park、Jaywoong Jeong、Zachary Wojtowicz、Yubin Kim、Taekyun Lee、Kaiqing Zhang、Asuman Ozdaglar\
> **机构**：MIT；KAIST；UT Austin；University of Maryland\
> **时间与版本**：v1 首次提交于 2026-10-28 01:15:54（北京时间）；本次阅读 v1 HTML，主线研究。

**研究问题**

多 Agent 任务往往把必要信息分给不同参与者。失败可能来自没找到证据、没让知情者发言，或最后没整合好已经交流的信息。只训练最终回答，很难判断通信过程是否真正改善；固定轮流发言也未必适合不同的信息分布。

**研究方法**

TeamGym 从法律、金融等材料构造“关键事实单元”：一组事实合起来足以支持决策，移走任一项就应造成信息不足。它将这些事实或包含事实的原文分给不同参与者，并明确谁能看见什么、谁能发言、何时结束。构造检查包括移除单项后的必要性判断与单个参与者无法独自作答的检查，但主要依赖模型核验，并非所有题都获得形式化保证。[§3](https://arxiv.org/html/2610.37571v1#S3)

训练有两种结构。协调者选人时，分别或共同训练共享参与者模型与协调者模型；当前发言人选人时，一个共享模型同时生成消息、选择下一个参与者、决定结束并作最终决策。后者的 harness 将成员目录、局部信息和通信记录整理成动作输入，限制只能选择合法成员，并把这些控制动作纳入策略梯度，直接训练了通信调度，而不只是测一个多 Agent 基准。[§5](https://arxiv.org/html/2610.37571v1#S5)

各策略从 Qwen2.5-7B-Instruct 开始，采用 GRPO 全参数更新。语义奖励由 GPT-5.5 按最终决策评分，并把组内优势传给受训动作；没有单独奖励“所有人都发言”或“找到更多事实”。格式非法或成员编号非法另给局部负优势并允许一次重试。金融共享策略实验每题采 16 条轨迹，80 次更新共 10,240 条 rollout，checkpoint 只按 FinDVer 验证集选择。[训练配置](https://arxiv.org/html/2610.37571v1#A7.SS3.SSS2)

**实际贡献**

贡献在于把信息分布、通信规则和可训练控制动作放进同一个可控环境，并通过交叉回放拆分通信轨迹与最终决策模型的作用。这比仅报告团队总分更接近“harness 的哪一部分被学会”。GRPO 与共享策略并非新方法；所谓涌现协调在本文中特指未被单独奖励的行为改变，不代表已经获得一般协作能力。

**结果与代价**

金融共享策略在 FinDVer 验证集的模型裁判分从 **21.85 升至 41.08**；在 40 道未见的四人 FinLongDocQA 测试题上，从 **33.50 升至 41.13**，提高 7.63 分。这些是归一化裁判分，不是客观答案准确率。训练主要见过两至三人的 FinLongDocQA，但在 FinDVer 中见过四人团队，因此不能把它解释为完全没见过四人协作。[§5.2、表 7](https://arxiv.org/html/2610.37571v1#S5.SS2)

在双方都完成决策的 **40 道验证题**上，固定最后决策模型、交换训练前后通信轨迹，平均收益为 **6.95 分**，95% 区间为 0.49—13.78；仅交换最终决策模型没有显著增益。这个诊断支持验证集收益来自通信，但它筛掉了未完成轨迹，不是全测试集结论。[附录 G.3.4](https://arxiv.org/html/2610.37571v1#A7.SS3.SSS4)

迁移证据较弱：法律共同训练在 CUAD 验证集从 11.97 到 22.38，MAUD 域外仅从 **5.12 到 5.58**。金融测试集的发言人数增加了，但固定一个外部决策模型后，通信内容带来的收益和关键事实覆盖增量均未显著；精确重复消息比例反而从 **23.1% 升至 48.6%**。每个训练配置使用 4 张 H200，均只报告一次训练运行，完整训练时长与裁判费用未给出。[§5.1.2](https://arxiv.org/html/2610.37571v1#S5.SS1.SSS2)、[附录 G.2.1](https://arxiv.org/html/2610.37571v1#A7.SS2.SSS1)、[G.3.5](https://arxiv.org/html/2610.37571v1#A7.SS3.SSS5)

**洞察评论**

这篇适合用来设计通信 harness 的训练评测：把“下一位是谁、什么时候停止”作为明确动作，与消息内容一起学习；再固定最终回答者，检查通信是否真增加了可用证据。

它最有用的边界是：更多参与者发言、更多轮通信与更好的任务结果并不等价。只用最终分数，策略可能同时学会更广的参与和更多重复。已有结果支持通信策略可以训练，但对跨域、跨信息分布的稳定收益仍需更大测试集与重复训练。

### Metacognitive Decoding：交互边界驱动的解码控制

> **原题**：[Metacognitive Decoding: Efficient Inference for Diffusion Language Agents](https://arxiv.org/html/2610.37642v1)\
> **作者**：Mingyu Zhao、Shuhang Lin、Ligong Han、Xiaojing Yu、Zhenting Wang、Yifei Pang、Yang Zhou、Dimitris N. Metaxas\
> **机构**：未核实；v1 HTML 与 LaTeX 署名区均只列邮箱，未列机构名称。\
> **时间与版本**：v1 首次提交于 2026-10-28 01:55:24（北京时间）；本次阅读 v1 HTML，并核对 LaTeX 署名。

**研究问题**

扩散语言模型一次并行处理一块 token，通过多轮修改逐渐确定文本。Agent 一旦生成完整工具调用，就应停下来等待环境返回；固定长度解码却可能继续计算后面的文本，最终被执行框架丢弃。另一类浪费是对重复的工具格式和复杂推理使用相同计算强度。

**研究方法**

先对 LLaDA-8B-Instruct 做工具轨迹 SFT，然后冻结主干，增加一个两层 Transformer 控制器。它读取 token 的置信度、已生成结构，以及当前交互轮次、工具调用或回答是否完成。更新对象是这个**生成控制组件**，并非继续更新整个语言模型。

控制器同时决定“哪些 token 可以确定”与“当前块还需计算多长”。前者利用轨迹中反复出现的工具格式作为候选片段，并调整逐 token 接受阈值；后者缩短有效计算范围。如果工具调用或回答尚未结束，就恢复更多位置继续生成，而不是把缩短长度等同于强制提前结束。

训练用当前控制器采集整条交互轨迹，以 GRPO 的组内相对奖励更新控制动作。失败轨迹奖励为零；答对时再按完整轨迹的相对 FLOPs 给效率奖励，成本包括主干与控制器。执行状态因此进入控制器输入，任务结果与执行成本进入 RL 反馈。[方法 §3](https://arxiv.org/html/2610.37642v1#S3)

**实际贡献**

主要增量是把工具调用的结束边界与可学习解码结合，减少环境不会消费的生成计算。GRPO、置信度解码和动态长度都不是本文首次提出；其价值在于给出明确的交互信号、控制动作和训练连接，并设置移除控制器的同主干对照。

**结果与代价**

在相同 SFT 主干下，BFCL Live 准确率从 **66.52% 到 70.96%**，每条轨迹计算量从 **32.49 到 18.48 TFLOPs**，下降 43.1%。五项任务的 FLOPs 降幅为 24.6%—43.1%，但准确率并非全部提高：MuSiQue 从 20.7% 降至 20.3%。换成 Dream-7B 并重新训练控制器后，MuSiQue 下降 2.2 个百分点，说明更激进的节省也会损伤任务表现。[表 1、表 3](https://arxiv.org/html/2610.37642v1#S4)

训练使用 8 张 A100，每阶段 40 轮。论文没有给出可直接核算的完整训练 GPU 小时和工具服务成本，主要指标是模型算术量，不能等同于实测端到端加速；主表也未给出重复训练的不确定性区间。BFCL 在所取子集内部按 1:1 分训练、测试，不能把结果当作未经任务适配的官方全量评测。[设置 §4.1](https://arxiv.org/html/2610.37642v1#S4.SS1)

**洞察评论**

可以把“这轮什么时候交给环境”当作可训练决策，而不只当作解码器的固定参数。这对并行生成尤其有意义：优化单位应是完整交互中真正被执行器使用的输出。

但本文依赖扩散解码内部的置信度和计算范围接口，不能直接套到普通自回归 API。实践中首先应测清工具调用之后有多少输出被丢弃，再判断训练专用控制器是否值得。

### Heads of Security：工具来源标签与注意力门控训练

> **原题**：[Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness](https://arxiv.org/html/2610.37657v1)\
> **作者**：Igor Shilov、Xiaoxue Yang、Alexander Panfilov、Evgenii Kortukov、Matthieu Meeus、Peter Romov、Wojciech Samek、Jonas Geiping、Yves-Alexandre de Montjoye\
> **机构**：Imperial College London；Tübingen AI Center；ELLIS Institute Tübingen；Max Planck Institute for Intelligent Systems；Fraunhofer HHI\
> **时间与版本**：v1 首次提交于 2026-10-28 01:58:52（北京时间）；本次阅读 v1 HTML。

**研究问题**

工具返回的网页、邮件或文档可能夹带指令。只在提示词里要求“把它当数据”，并不能保证模型保留来源边界。本文研究将执行框架已知的来源标签直接传进模型，并训练不同注意力头怎样使用这些输入。

**研究方法**

输入 token 被分为 trusted、untrusted、template 三个通道：系统和用户内容通常可信，工具返回通常不可信，角色分隔符单列。AgentDojo 中每个工具返回 token 都标为 untrusted；网页任务则区分固定界面元素与可能由用户编辑的内容。这里需要 harness 提供正确的来源标记，模型自己不负责判断谁可信。[输入机制 §3](https://arxiv.org/html/2610.37657v1#S3)、[执行接口附录 G](https://arxiv.org/html/2610.37657v1#A7)

每个注意力头增加一组可训练的通道门控：它可以降低某类输入的注意力，而不强制所有头都屏蔽该输入。主干参数冻结，使用 DPO 训练门控；偏好对中，正例遵循用户要求，负例遵循不可信内容中的注入指令。GPT-OSS-20B 更新 18,432 个门控参数，Llama-3.3-70B 更新 46,080 个。[训练 §3.3](https://arxiv.org/html/2610.37657v1#S3)

部署时沿用同样的通道标记和门控。因此联动发生在**工具来源接口 → 带信任标签的偏好训练 → 受训模型读取工具结果**，并不是只在 Agent 基准上测试一个通用防御。GPT-OSS 还使用教师生成的推理轨迹补充偏好选项；这些不等于重新训练执行 Agent 的完整任务策略。[附录 J](https://arxiv.org/html/2610.37657v1#A10)

**实际贡献**

本文沿用已有偏好数据和 DPO，改变的是可学习对象及输入来源约束。少量逐头门控提供了一种比大范围微调更受限的适配方式，也让训练与部署必须共享的信任接口变得明确。不能把“参数少”直接解释为训练和部署成本都很低。

**结果与代价**

在所测 RL-Hammer 攻击集合中，GPT-OSS-20B 的最高攻击成功率为 **97%**，SecAlign 为 **85%**，HoS 为 **10%**；这是该组训练目标及迁移攻击中的最大值，不是任意攻击下的安全保证。[表 1](https://arxiv.org/html/2610.37657v1#S4)

实际任务存在明显取舍。GPT-OSS 主配置在 AgentDojo 上将攻击成功率从 23.78% 降到 1.09%，无攻击任务成功率则从 66.32% 降到 63.16%。在 AgentDyn 上，攻击成功率从 38.21% 降到 0.89%，但无攻击成功率从 **58.33% 降到 41.67%**。不能只展示防御数字而忽略正常能力损失。[完整对照表 13](https://arxiv.org/html/2610.37657v1#A7)

训练使用 8 张 H100 80GB；GPT-OSS HoS 主配置训练 1 个 epoch、256 步，SecAlign 为 3 个 epoch、768 步，输入包装也有差别。论文没有完整训练费用对照，且门控要求修改注意力实现，不适用于只能调用黑盒 API 的环境，也不能直接用于没有显式 token 对注意力的纯线性架构。[训练配置](https://arxiv.org/html/2610.37657v1#A10)、[限制 §6](https://arxiv.org/html/2610.37657v1#S6)

**洞察评论**

对训练数据管线，值得保留的是每段内容的来源及授权边界，避免把工具结果、用户要求和模型生成内容压平成没有来源的文本。本文证明这些标签可以成为后训练接口，但并不负责解决来源标错或用户确实要求遵循外部说明的情形。

如果正常任务本来就需要执行文档中的操作指引，严格抑制外部指令可能损伤功能。采用这类组件时，应同时评价攻击成功率和正常任务成功率，并将接口标记规则与模型版本一起管理。

## 领域结构与研究进展

### 训练数据：生成哪些任务，下一批又选哪些任务

训练数据量只是起点。一个 Agent 的轨迹由任务目标、工具集合、初始状态、执行策略和验收规则共同决定：重复生成相同执行结构，不一定带来新的学习信号；扩大环境种类，也不保证当前策略已经能从中学到东西。

**SynthAPI 解决静态供数的构成问题，EnvSched 解决训练过程中持续选题的问题。** 前者在造数前分配工具、指令与数据库状态，生成成功轨迹后做 SFT；后者根据当前执行模型的奖励统计调整 GRPO 任务批次。它们可以放在同一条训练管线上，但本文没有验证组合收益，也不能将 SFT 的配比规律直接当成 RL 的最优课程。[SynthAPI 配比实验](https://arxiv.org/html/2610.37648v1#S4.SS2)、[EnvSched 方法与消融](https://arxiv.org/html/2610.37609v1#S3.SS3)

与传统的数据混合、课程学习相比，这两篇新增的观察单位是**执行环境的结构与状态**。对本主题更可取的做法，是先给现有轨迹加上工具族、初始状态类型、验收器与策略版本，再在固定预算下比较配比或调度；不是先追求更大的生成总量。EnvSched 的同 rollout 对照较直接，SynthAPI 的等任务数对照还不能消除 token 和构建费用的差别。

### 交互反馈：任务变好，是否真因为过程学对了

最终成功率能告诉训练器“结果如何”，却未必能指出错误来自哪一个工具操作、哪次发言选择，或最后的答案整合。因此，需要把过程表示得足够明确，才有可能核查信用分配。

**PerceptRL 把视觉操作变成可定位的过程反馈；TeamGym 则把通信内容与最终回答者拆开检验。** 前者通过目标声明、坐标和实际重执行观察，将局部奖励分到对应轮次；后者固定最终决策模型并替换通信轨迹，检查团队分数是否确实来自更好的沟通。这些分别服务于训练监督和效果归因，不能互相替代。[PerceptRL 奖励接口](https://arxiv.org/html/2610.37471v1#S3.SS3)、[TeamGym 交叉回放](https://arxiv.org/html/2610.37571v1#A7.SS3.SSS4)

两篇也说明了同一个限制：**更符合过程指标，不自动等于更好的任务表现。** 定位准确还可能操作了不必要的对象；发言更广也可能增加重复消息。现有证据支持具体接口和受控实验的价值，不支持“过程奖励一定优于终局奖励”或“通信越多越好”。对于新 harness，应保留原始动作与观察，并用未参与选模的测试集同时验证过程变化和最终收益。

### 受训组件：执行模型之外，还有生成与信任控制

后训练不一定更新整个 Agent 模型。只要执行流程暴露了稳定接口，也可以训练一个较小的控制组件：Metacognitive Decoding 使用工具调用是否完成来控制解码，Heads of Security 使用内容来源标签来控制注意力。

**这与纯推理期规则优化的区别，在于接口信号真正进入了参数训练。** 前者用交互结果和计算成本训练 GRPO 控制器；后者用带来源通道的偏好对做 DPO。它们都要求部署时继续提供相同接口，无法仅靠复制一段提示词获得论文结果。[解码控制训练](https://arxiv.org/html/2610.37642v1#S3)、[信任门控训练](https://arxiv.org/html/2610.37657v1#S3)

代价也必须按最终目的计算：FLOPs 下降未必对应工具调用链的实际提速，攻击成功率下降也可能伴随正常任务能力损失。两篇更适合用来理解**哪些控制变量值得训练，以及训练后牺牲了什么**；它们尚不能证明小组件在总成本上普遍优于全模型微调。

## 总结与启示

- **优先阅读 EnvSched。** 对已有 Agentic RL 管线，它最直接回答“现有任务池下一批该采什么”，并提供同训练步数、同 rollout 数的对照。先确认环境结构与奖励是否可靠，再尝试其调度思路。
- **轨迹应保留执行语义。** 除了文本，至少记录工具与环境版本、初始状态、动作目标、真实观察、来源标签和奖励落点；本文中的训练接口都依赖这些具体信息。
- **把训练收益拆开验证。** 生成更多数据、改数据配比、改调度、增加过程奖励和更新控制器是不同干预，不能用一组最终总分替代各自的贡献对照。TeamGym 的负结果尤其提醒：行为变化也需要测试集验证。
