### SWE-Trail：历史引导的分支采集

> **原题**：[SWE-Trail: History-Guided Trajectory Collection for Coding Agent Training](https://arxiv.org/html/2611.02074v1)\
> **作者**：Ziming Li、Lu Yu、Jiatan Huang、Qing Cui、Jun Zhou、Chuxu Zhang\
> **机构**：University of Connecticut；Ant Group\
> **时间与版本**：v1 首次提交于 2026-11-02 01:26:42（北京时间）；本次阅读 2611.02074v1 HTML；主线研究。

**研究问题**

编码 Agent 在同一问题上多采几次，往往重复此前路线。把失败总结直接塞给下一次执行虽能帮助解题，却可能让学生学会依赖部署时没有的建议。论文把历史用于采集器的预算分配，而不是作为编码模型的额外提示。

**研究方法**

采集器先读取同题旧轨迹并做只读仓库检查，编译出检测规则：遇到反复阅读但不验证等状态时，才启动局部比较。规则在该轮固定，参考补丁和公开修复均不可见。

触发后，GLM-5.1 在 OpenHands 中仅从普通上下文采样下一步动作。采集器将默认动作与一个备选动作放进同检查点的两个隔离工作区，短暂执行、打乱展示顺序，再按真实仓库证据选择继续路线；每条轨迹最多比较一次。导出时保留模型原始思考与动作，删除未选分支和私有采集信息。

300 个问题各收集 5 条轨迹，共 1,500 条，不论最终成功与否均进入学生的全参数 SFT。历史只影响“走哪条路”，不成为学生输入；主学生使用 128 张 H800。[方法与实验设置](https://arxiv.org/html/2611.02074v1#S3)

**实际贡献**

有价值的增量是把历史辅助约束在采集器侧，并用下游训练检验轨迹价值，而不是仅比较采到多少成功补丁。检查点、分支搜索和历史总结都有前作；本文给出它们在信息边界明确条件下的组合对照。

**结果与代价**

124B 学生在 SWE-bench Multilingual 上从独立采样的 **63.33% 到 65.67%**，SWE-Pro 从 **41.22% 到 42.82%**；同样数据量、背景数据及训练配方，均为三次独立训练均值。相对没有历史的同管线 H0，增益为 2.22 和 0.87 点，但按测试题配对 bootstrap 的 95% 区间分别为 −0.2 至 4.6、−0.8 至 2.5，均跨零。[结果 §4.2](https://arxiv.org/html/2611.02074v1#S4.SS2)

历史从 5 次扩到 10 次，总采集 token 再增 **12.9%**，两项均分只多 0.22、0.14 点。H5 相对 H0“最多多 3.7% token”的口径不含旧历史采集成本，且 H0 编译器成本漏计为下界；不能当成完整项目只多 3.7%。目前只验证一种采集模型和 scaffold。[成本与限制](https://arxiv.org/html/2611.02074v1#S4.SS3)

**洞察评论**

优先借鉴两个接口：可恢复的执行检查点，以及采集器私有信息与模型可见信息的分离。这样能使用成功、失败历史改进供数，同时保留学生在部署时真正具备的信息条件。

更多成功轨迹不是唯一目标：无历史管线也能增加成功采样，却不产生同样的学生收益。实际选管线时，应固定训练量比较持出任务，并把旧轨迹、编译、分支执行的费用全部计入。


### CARE：先归因，再从生产失败中学习

> **原题**：[CARE: Grounded Recursive Self-Improvement for Production Customer-Service Agents](https://arxiv.org/html/2611.02839v1)\
> **作者**：Yanbei Jiang、Chao Lei、Rena Gao、Xiaochen Zhao、Yuchen Ge、Haohang Liu、Runze Nie、Qitian Chen、Qi An、Haolin Song、Yufei Sun、Yihao Ding、Jey Han Lau、Krista A. Ehinger、Xingjun Ma、Weijia Chen、Ruiyuan Wu、Zhen Luo、Ke Xing、Yongjun Yin\
> **机构**：AI and Data Team, Keeta, Meituan；University of Melbourne；Fudan University\
> **时间与版本**：v1 首次提交于 2026-11-02 17:39:52（北京时间）；本次阅读 2611.02839v1 HTML；主线研究。

**研究问题**

生产中的失败可能来自模型，也可能来自规则、路由、工具或评审器。若都当成坏回答训练，模型会被迫绕过坏接口，甚至学会凭事后结果编造当时不可知的信息。

**研究方法**

CARE 先收集完整对话、工具结果、Skill/SOP、运行状态和评审版本，经独立复核确认错误，再做归因。工具、Harness、规则和基础设施故障进入各自修复路径，只有模型行为错误形成后训练样本。可重放时分别改变模型、规则和接口；不能隔离原因的案例保留未知标签。

对模型错误，按请求身份锚定首个错误决策，截断其后内容。修复只能替换这一个决策，须满足当时工具合同和可见证据；后续结果及诊断只给教师。冻结的同模型教师在学生自己生成的 token 前缀上提供概率分布，学生通过截断 KL 类损失更新；这一步是自蒸馏，不是把整段事故聊天重新做行为克隆。

不同 SOP 版本的事故按发生时规则解释，混合训练以维持条件化行为。新版本需通过从最新 SOP 编译、随后冻结的模拟测试、离线轨迹检查及同期在线比较，再经人工批准。[归因 §5.2、学习 §6](https://arxiv.org/html/2611.02839v1#S6)

**实际贡献**

局部修复、自蒸馏和发布门禁本身并不新。增量在于把故障归因、首错信息边界、规则版本和发布验证放进同一条生产学习链路，并保留不应进入训练的事故类别。

**结果与代价**

从冷启动 V0 到五轮改进后的 V5，559 例冻结模拟测试准确率 **93.00%→94.10%**，确认 Bad Case 率 **6.42%→1.97%**。指标并非单调：V3 模拟准确率曾达 95.30%；V5 以部分完成率换取更低的错误率。同期 GPT-5.4 为 96.80% 与 4.60%。[表 6–7](https://arxiv.org/html/2611.02839v1#S8.SS2)

V5 在线满意度与同期 incumbent 的差异没有统计显著性，结论是达到持平，不能写成已经超过。按全部流量替换核算，服务单成本降低 70.5%，但这是模型 API、H20 服务与固定机器成本的口径，不含完整事故复核和训练成本。各轮 Harness 也持续维护，因此跨轮绝对增益不能全部归因给模型权重；同期两组使用同样 Harness。[评测设置与费用](https://arxiv.org/html/2611.02839v1#S8)

**洞察评论**

对已有 Harness，最有用的供数对象是“这个请求下的第一个错误决策”，而非事故结束后重写一条完美长轨迹。保留原始输入、规则版本和未来信息边界，可以减少训练数据中的事后聪明。

这条路线同时依赖可审计的状态、足够可靠的错误复核和合法的局部修复；这些是系统能力，不能用一个训练损失替代。


### NorthCUA：从环境执行到模型更新的共用接口

> **原题**：[NorthCUA Technical Report: Turbocharging Computer-Use Agents through Experience at Scale](https://arxiv.org/html/2611.02102v2)\
> **作者**：NorthCUA Team\
> **机构**：Shanghai Qiji Zhifeng Co., Ltd.\
> **时间与版本**：v1 首次提交于 2026-11-02 02:16:47（北京时间）；本次阅读 2611.02102v2 HTML；主线研究。

**研究问题**

GUI Agent 的训练经验不能只是一串截图与点击。长任务会产生压缩后的输入、跨应用文件、未确认的完成状态以及不同版本策略生成的片段；若这些信息在导出时丢失，训练样本就可能和实际决策不对应。

**研究方法**

NorthCUA 将模型下次决策可见的上下文与完整执行记录分开。前者使用有限截图窗口、旧历史压缩和显式工作记忆；后者保留动作、观察和产物供检查与学习。执行结束后，评审 Agent 可读取记录及仍存活的工作区，按任务要求继续核验；不确定和基础设施异常不冒充已验证完成。

经验先用于广泛 GUI mid-training，再用约 3,000 条、31 万 GUI 步的已验收长程轨迹做 SFT。之后从约 1,500 个桌面和 500 个 Web 任务池做联合在线 RL，沿用相同观察与动作约定。

在线训练按任务组的终局奖励构建相对优势，并对生成 token 使用 PPO 式截断目标。异步长轨迹可跨行为策略版本，系统为每段保存采样时概率及版本，作为重要性比率分母。作者明确承认：在策略滞后和状态分布变化下，这仍是近似的离策略修正。[Harness §3、学习 §5、附录 E](https://arxiv.org/html/2611.02102v2#S5)

**实际贡献**

主要贡献是端到端系统和数据契约，而不是新的 RL 目标。值得单独借鉴的是上下文与原始记录分层，以及环境一直保留到验收和记录交付之后；它们决定训练器是否拿得到可信样本。

**结果与代价**

相同模型 RL 前后对照中，Nano 的 OSWorld-Verified **76.1%→78.9%**，WebArena-Verified **64.2%→67.2%**；Pro 分别 **85.9%→88.6%**、**69.6%→73.9%**。Mini 的 OSWorld 2.0 二元成功率却保持 18.5%，说明提升并非每个指标都有。[表 13](https://arxiv.org/html/2611.02102v2#S6.T13)

较大增益出现在整个阶段管线中，不能由此单独证明压缩、记忆或验收器的因果收益。桌面同时报告二元成功与部分进度，不应混比；跨机构榜单还存在动作接口和步数差别。广泛阶段超过 10 万条轨迹、400 万 GUI 步，加上验收和在线执行，报告没有将其统一成等总预算对照。[阶段数据与比较限制](https://arxiv.org/html/2611.02102v2#A9)

**洞察评论**

搭建 Agentic RL 管线时，可先把三种对象分开保存：真实环境发生了什么、模型当时实际看到了什么、训练时哪些 token 由哪个策略生成。只有这样，压缩、异常过滤和异步采样才有可能被正确复现。

这篇适合作为架构参考；模型最终分数更多说明整条链可工作，不说明每个组件都已被独立消融证明。


### SCOPE：从可复用局部技能扩展到完整任务

> **原题**：[From Local Skills to Long-Horizon Web Tasks: Progressive Skill Exploration for LLM Web Agents](https://arxiv.org/html/2611.03116v1)\
> **作者**：Xueyang Feng、Xiaohe Bo、Xu Chen、Quanyu Dai、Feng Wen\
> **机构**：Gaoling School of Artificial Intelligence, Renmin University of China；Huawei Technologies Ltd.\
> **时间与版本**：v1 首次提交于 2026-11-02 21:32:59（北京时间）；本次阅读 2611.03116v1 HTML；主线研究。

**研究问题**

长程 Web 任务前几步做对、后面失败时，整条轨迹的零分会掩盖已经掌握的能力。SCOPE 希望复用这些局部进展，把环境推进到尚不会处理的位置，再花预算探索。

**研究方法**

辅助模型把执行历史切成有环境反馈的子任务段：完成局部目标的存入技能库，失败模式另存。技能库构成状态图，系统选择访问较少的前沿，并回放技能链恢复到该处。网页元素会变化，因此回放时先将原索引转换为语义名称，再定位当前页面元素。

在前沿的第一个动作上，系统用教师或当前策略结合失败经验进行干预，随后继续正常探索。最后将真正执行成功的技能链蒸馏到学生；目标是对轨迹状态—动作对做负对数似然学习，学生不再接收额外失败经验。作者称其为 agentic OPD，强调交互状态可达；它与逐 token 师生分布 KL 的 OPD 并非同一种实现。[方法 §3](https://arxiv.org/html/2611.03116v1#S3)

**实际贡献**

局部技能记忆和回放已有基础。具体增量是把局部进度、失败对齐的前沿干预与最终的无额外记忆条件策略训练联结；对照支持这条组合有效，但不能将总增益全部归为某一个记忆设计。

**结果与代价**

Llama3.1-8B 在 WebArena-Lite 上从所列最强 WebRL 基线 **45.8% 到 54.3%**，增加 **8.5 个百分点**，表中的 18.6% 是相对增幅。WebShop 上 GRPO 为 **76.2%**，SCOPE 为 **85.2%**；真实 WebVoyager 从 RFT 的 **37.3% 到 42.8%**。[表 1–3](https://arxiv.org/html/2611.03116v1#S4.T1)

辅助模型默认使用 DeepSeek-V3.2，也测试了微调的 Llama 自管理版本；记忆分析和回放都不是免费。成本分析覆盖调用数与交互数，并未等同完整 token/GPU/环境费用；部分不可访问站点被过滤，且最大动作步数因基准而异，不能把结果视为原始全量网页任务的一致测量。[设置 §4.1](https://arxiv.org/html/2611.03116v1#S4.SS1)

**洞察评论**

值得为失败轨迹多保存“已达成的子目标”和可重执行前缀，而不只保存最后失败原因。它能将局部成功变成下一轮探索的起点。

迁移时，前沿恢复必须真实可达、技能需适应当前页面。只拼接日志而不重执行，可能得到状态不连续的伪成功训练轨迹，失去本文证据所依赖的条件。


### RLiD：把动作接口直接变成训练策略空间

> **原题**：[RLiD: Reinforcement Learning in the Decision Plane for Language Agents and LLMs](https://arxiv.org/html/2611.02455v1)\
> **作者**：Ziyi Chen、Yan Zhang、Jianhui Wei、Jianing Yin、Daoan Zhang\
> **机构**：University of Illinois Urbana-Champaign；National University of Singapore；Zhejiang University；University of Pennsylvania；University of Rochester\
> **时间与版本**：v1 首次提交于 2026-11-02 11:17:51（北京时间）；本次阅读 2611.02455v1 HTML；主线研究。

**研究问题**

环境真正执行的是一个动作，但常规 token RL 把同一个优势传播给描述动作的措辞、思考和格式 token。RLiD 检查：如果直接优化可执行动作的概率，训练与执行是否能更对齐。

**研究方法**

编译器从观察和非特权历史生成有限动作菜单，可附紧凑记忆；模型在一次前向中读取标签概率并选择动作，不再生成长文本或解析格式。菜单来自环境原生合法动作或预先写定的规则，不是对任意开放工具接口自动成立的能力。

执行完整任务得到回报，使用 GRPO 或带同状态分组的 GiGPO 优势，按决策概率做 PPO-clip，只更新 rank-16 LoRA。训练还要随机打乱菜单，并抑制模型对某个标签字母的偏好。之后可将成功决策作为监督，蒸馏给其他决策模型，或教生成式 LLM 输出原生动作字符串。[§2–3](https://arxiv.org/html/2611.02455v1#S2)

**实际贡献**

动作选择式语言控制和蒸馏均有前作。本文的有用增量是将接口、概率优化和信用审计放在同一框架；理论只说明同一文本策略内部边缘化措辞可去掉一个零均值噪声项，不证明换参数化后的模型一定胜过生成式策略。

**结果与代价**

同运行器 Sokoban 对照中，Qwen2.5-0.5B 在 300 次更新后，决策模型测试成功率 **44.5%±2.7%**，仅输出答案的 token 模型为 **16.3%±8.4%**；每次训练记录为 2.3 对 2.9 GPU 小时。去掉字母偏好正则后，决策模型只剩 **5.9%**，因此不能把全部收益归为取消文本生成。[表 2](https://arxiv.org/html/2611.02455v1#S4.T2)

ALFWorld 的高分依赖可编译动作及结构化记忆，教师训练、学生蒸馏和后续 RL 成本应共同计算，不能只引用学生 RL 时间。论文在开发期反复记录测试曲线，承认存在适应性窥视；表中因而报告最终检查点，并补充验证选择结果。小型网格任务的收益不能直接外推到自由工具调用。[设置与蒸馏](https://arxiv.org/html/2611.02455v1#S3)

**洞察评论**

对动作空间可列举的 Harness，可把“可执行动作 ID”设为稳定训练接口，再让模型负责选择，减少格式错误和不必要 token。也可以先训练这种便于验证的策略，再将动作轨迹教给通用生成模型。

接口提供的状态与动作候选本身就是能力来源，比较时必须固定它们。决策空间变清楚，不代表跨时间的信用分配问题已经解决。


### Think with Skills：训练先把技能写成操作流程

> **原题**：[Think with Skills: Pseudocode Planning Before Execution for Advanced Reasoners](https://arxiv.org/html/2611.02830v1)\
> **作者**：Boshen Zhou、Boxuan Yue、Xiang Li、Shanchao Yang\
> **机构**：Honor Device Co., Ltd., China.\
> **时间与版本**：v1 首次提交于 2026-11-02 17:29:30（北京时间）；本次阅读 2611.02830v1 HTML；主线研究。

**研究问题**

技能文档可能知道“应该做什么”，却没有明确当前文件、工具和条件下该先做哪一步。模型还需要把多项技能的输出、输入和失败分支接成实际程序。

**研究方法**

训练要求模型先生成任务专用伪代码，列出操作步骤、输入产物、条件分支、依赖和验收标准，执行时检查当前步骤的前提，失败后只修对应部分。伪代码由模型遵循，不交给外部解释器运行。

数据管线从技能图采样组合，生成任务、输入文件和验证器，由强弱两个 Solver 检查可解性与难度；排除 SkillsBench 的 174 项评测技能。先对“伪代码—工具执行”轨迹做 SFT，再由终局验证器给完整 rollout 奖励，用 GRPO 同时更新计划生成和实际执行。[方法 §3](https://arxiv.org/html/2611.02830v1#S3)

**实际贡献**

程序化规划、技能组合与 GRPO 都是已知手段。本文贡献是具体的训练数据构造和同模型分阶段对照，而不能把“先计划再执行”本身称作新思想。

**结果与代价**

同为 Qwen3.5-35B-A3B、Claude Code 运行框架，SkillsBench 成功率从直接用技能的 **35.0%**，到伪代码提示 **45.0%**，再到 SFT **60.0%**、SFT+GRPO **62.0%**。因此大部分报告增益已经在监督阶段出现，GRPO 是最后 **2 个百分点**。[表 2](https://arxiv.org/html/2611.02830v1#S5.T2)

单技能与多技能训练分别用 901、913 个例子，成绩 55.0% 与 60.0%，支持组合训练值得关注，但并未完全对齐任务难度。正文称会给超参，实验设置段实际缺少足够具体的采样组、训练步数和完整成本，也未给独立训练种子方差；不同框架的外部模型分数只能作参考。[实验与分析](https://arxiv.org/html/2611.02830v1#S4)

**洞察评论**

可把现有技能文档转成训练契约：每个操作需要什么、产生什么、失败后怎么检查，随后收集计划与真实执行能否对上的样本。

先做同模型“仅改提示”和“SFT”对照，再决定是否值得上 RL。该论文的分阶段结果本身就说明：增加 RL 并非全部收益的来源。


### DR Pixel：给检索动作分配监督权重

> **原题**：[DR Pixel: Page-Native Deep Research with Vision-Language Models](https://arxiv.org/html/2611.03097v1)\
> **作者**：Tiansheng Hu、Yichuan Wang、James V. Talwar、Nicholas Tomlin、Chen Zhao、Sewon Min\
> **机构**：NYU Shanghai；University of California Berkeley；Rational Dynamics；Toyota Technological Institute at Chicago；New York University\
> **时间与版本**：v1 首次提交于 2026-11-02 21:13:42（北京时间）；本次阅读 2611.03097v1 HTML；主线研究。

**研究问题**

教师轨迹成功，不代表其中每一次搜索都值得模仿。普通 SFT 会同时复制关键查询、绕路和重复操作，使学生更会找证据，也可能更爱搜索。

**研究方法**

该 Harness 直接检索完整页面图像，而非先拆成 OCR 文本。GPT-5.4 生成训练轨迹；冻结基座用标准答案的对数似然衡量当前历史对答案的支持。推理段通过删去该段评估贡献；搜索段比较加入返回证据前后，二者按不同规则计分。

非正贡献步骤被屏蔽，正贡献按各自类型排序赋权，再联动检查推理是否帮助形成其后动作。最后对推理、搜索动作及最终答案做加权 token 损失，只用 LoRA 更新 Qwen3.6-27B，一轮训练、4 张 H200。部署时不需要标准答案或这次反事实评分。[训练 §5.1](https://arxiv.org/html/2611.03097v1#S5.SS1)

**实际贡献**

核心增量是将检索接口里的动作与证据返回转成细粒度 SFT 信号，而不是简单丢掉整条失败轨迹。信用分数来自冻结模型的答案似然代理；并未重新执行完整后缀来证明每步对最终结果的因果效应。

**结果与代价**

同一 27B 模型在 DRPixelBench 上，未训练为 **40.1%** 准确率、每题 **8.8** 次工具调用；普通 SFT 为 **49.0%**、**14.0** 次；加权训练为 **52.1%**、**8.9** 次。对普通 SFT 多 3.1 个百分点，同时减少约 5.1 次搜索；结果为三次运行平均，不等同三次独立训练。[表 4](https://arxiv.org/html/2611.03097v1#S5.T4)

加权训练的金标准页命中率 52.0%，略低于普通 SFT 的 53.6%，因此收益并非所有检索指标都提高。代价还包括生成教师轨迹与离线逐步评分，训练 GPU 数量不能替代总成本；模型似然未必准确表示对人可用的证据价值。

**洞察评论**

对 Harness 供数，建议保留“动作—返回证据”的成对结构，允许成功轨迹内部的无效搜索得到较小权重。它比只按最终成功过滤更细，也便于查学生为何增加工具调用。

迁移到代码和浏览器任务时，需要重新验证步骤价值代理。删除观察可能破坏后续上下文，只看答案似然也可能偏向模型熟悉的表述；不能直接拿来充当客观环境奖励。


### TriGRPO：成功动作引导的同状态分支

> **原题**：[Hindsight Credit Assignment over Trees for Agentic RL](https://arxiv.org/html/2611.02706v1)\
> **作者**：Penghong Zhao、Yihao Chen、Maoheng Yuan、Yunjian Zhang、Abudukelimu Wuerkaixi、Haoran Xu、Man Lv、Yaolong Wang、Zhijie Sun、Guohua Liu、Yuewei Zhang\
> **机构**：Alibaba Cloud Computing；Fudan University\
> **时间与版本**：v1 首次提交于 2026-11-02 15:56:53（北京时间）；本次阅读 2611.02706v1 HTML；主线研究。

**研究问题**

同一题的独立采样可能全部失败，也可能全成功；两种情况都让组内相对优势消失。即使偶尔找到了好动作，普通轨迹采样也不容易利用它解释其他失败。

**研究方法**

系统在当前题的成功轨迹库中寻找与进行中轨迹相同的决策状态。若动作不同，就从当前前缀生成兄弟分支，替换为已发现的成功动作，再让当前策略继续执行，实际比较两条后缀结果。

训练把三层反馈合并：树根间的组相对回报、父—兄弟分支结果差、按任务及任务类型收缩的历史回报基线。受干预分支不进入历史基线估计；注入的成功动作另有行为克隆辅助，权重逐步下降。默认分支信用只用于分支点后的 token，避免把后续成功盲目写回共享前缀。[§3.3](https://arxiv.org/html/2611.02706v1#S3.SS3)

**实际贡献**

前缀共享、反事实分支与历史基线已有前作。具体贡献是成功动作引导的分支和三层信用组合，以及对前缀奖励污染的实证检查；它不是无需环境恢复就能离线完成的算法。

**结果与代价**

Qwen2.5-3B 的 ALFWorld 汇总成绩为 **93.8%**，GiGPO 为 **87.6%**，报告到峰值的 token 为 **0.338B 对 0.360B**。但论文将这一结果写成“测试划分上的 peak validation SR”，因此不能把它当作只在独立验证集选模后的最终测试泛化。[表 1](https://arxiv.org/html/2611.02706v1#S4.T1)

成本优势也非所有规模成立：7B 版本为 0.319B token，GiGPO 为 0.265B，后者更少。三次种子平均和峰值前 token 不能代表完整训练预算；状态匹配、成功库管理及环境分支恢复也需额外工作。

**洞察评论**

成功轨迹可以提供“在哪个已见状态尝试另一动作”的种子，而不只作模仿数据。保存父分支、替换动作、后缀回报与共享前缀边界，有助于训练器只把信用发给实际变化的部分。

这种比较仍可能受随机环境和后续采样影响，并不因叫反事实就自动成为无噪声因果标签。评估时应固定最终训练预算与独立选模规则。


### E-GenRM：从真实行为构建可用于训练的评审

> **原题**：[E-GenRM: Generative Reward Modeling for Open-Ended E-Commerce Shopping Agents](https://arxiv.org/html/2611.03008v1)\
> **作者**：Ying Sun、Qiuyu Zhao、Xiao Wang、Xiyu Zhao、Gege Shi、Zenghui Sun、Jinsong Lan、Haihong Tang、Bo Zheng\
> **机构**：Taobao & Tmall Group of Alibaba；Technische Universität Wien\
> **时间与版本**：v1 首次提交于 2026-11-02 20:10:57（北京时间）；本次阅读 2611.03008v1 HTML；主线研究。

**研究问题**

开放购物目标不能只验“有没有找到产品”。用户历史中隐含的偏好、当前明确要求和产品事实可能互相制约，需要可追溯的标准来解释为什么一个回答更合适。

**研究方法**

系统从以购买结束的行为链倒推决策点，将搜索与筛选事件转成工具调用及返回，把当时可见上下文与之后的购买结果分开。后者只构造偏好标签。教师据可见证据生成加权评审准则、理由及引用；人工抽查 500 个训练决策点，翻译和标签通过率为 94.2%。

奖励模型先 SFT 学评审链，再通过 GRPO 同时奖励偏好正确和各准则的事实支持，最后强调个性化难负例。主动检索扩展在信息不足时补证据。下游购物 Agent 中，同一初始化、任务池和更新预算下，用该评审器产生 DPO 偏好对或 GRPO 奖励。[方法 §4、应用 §5.5](https://arxiv.org/html/2611.03008v1#S4)

**实际贡献**

行为推断偏好和生成式奖励已有前作。本文较实用的增量是把决策可见性、证据验证、评审训练与真正的下游策略训练接起来，并比较不同监督源，而非只证明奖励模型自己更会打分。

**结果与代价**

在含 373 个专家标注决策点的基准上，27B 纯模型偏好准确率为 **82.57%**；加入检索后才是摘要的 **87.40%**。下游购物 Agent 的离线总体评分，GRPO 用专业 Judge 为 **0.715**，用 E-GenRM 为 **0.728**；DPO 为 **0.686→0.705**。这些是内部评分，不是成功率。[表 1、6](https://arxiv.org/html/2611.03008v1#S5.T6)

14 天 A/B 报告有效辅助率增加 **1.39 个百分点**、满意度增加 **2.33 点**，p 值分别 0.0433、0.0082。证据来自同一商业平台、内部评测及行为翻译；公开任务上的可复用性仍有限。主动检索、强教师与逐准则验证增加成本，文中未给可复用的全链费用对照。[表 7](https://arxiv.org/html/2611.03008v1#S5.T7)

**洞察评论**

奖励数据也需要与轨迹一样严格的时间边界：未来行为可以帮助定义标签，但不能悄悄出现在学生当时的上下文。这个原则对点击、购买、人工接管或最终任务结果都适用。

将奖励模型接进 Agent 后训练之后再测真实收益，比单独比较 Judge 分数更有说服力；但应同时检查它是否只学会平台已有偏好，以及信息检索的额外成本是否抵消收益。


## 领域结构与研究进展

本期围绕三层组织：**经验生产 → 历史和技能如何改变采样；学习接口 → 决策、步骤和未来信息的边界；运行系统 → 版本、状态与验收如何进入训练**。

### 1. 经验生产：历史应放在采集器还是模型输入中

成功轨迹稀少时，最直接的方法是增加独立采样，但重复路线会消耗预算。SWE-Trail 用历史决定在哪个状态多试一条路，并将这部分私有信息挡在学生上下文之外；SCOPE 则从局部技能回放到探索前沿，用失败经验干预后续动作，再将成功链蒸馏给标准输入下的学生。两者都复用旧经验，却分别约束**采集决策的信息边界**和**环境进度的可复用性**。[SWE-Trail](https://arxiv.org/html/2611.02074v1#S3)、[SCOPE](https://arxiv.org/html/2611.03116v1#S3)

TriGRPO 进一步把分支比较嵌进在线 RL，用同状态的成功动作启动兄弟分支。它产生的是相对信用，而非只增加示范数据。选择这条路线需要状态恢复与前缀边界；选择技能回放则需要可靠的元素重定位与子目标验收。它们不能只凭最终成功率互相排名，环境可恢复能力和额外调用预算不同。

### 2. 学习接口：该学习的是动作、证据还是事后修复

环境只执行解析后的动作，RLiD 因而把有限动作菜单直接作为策略空间，减少措辞与格式对训练的干扰。Think with Skills 保留生成式操作，却先训练模型把技能写成可检查流程。前者适合动作可列举的环境；后者允许开放工具与文件，但额外计划可能出错，仍需验收，不能假定伪代码天然可执行。[RLiD](https://arxiv.org/html/2611.02455v1#S2)、[Think with Skills](https://arxiv.org/html/2611.02830v1#S3)

对已经存在的长轨迹，DR Pixel 区分值得模仿与应少学的检索步骤；CARE 则只在首个模型错误处构造受验证修复。一个改变 SFT 的步骤权重，一个改变训练决策的截断位置。它们共同提醒：最终成功或失败标签太粗，监督应落到可解释的行为位置；但似然代理和事故诊断都有误差，不能直接称为客观因果贡献。

**未来信息可以帮助构造监督，不能成为学生当时的证据。** CARE 将后续结果、诊断和修复放在教师侧；E-GenRM 用购买后的行为形成偏好，却只给评审器决策时可见上下文。与普通“把失败改写成成功答案”的区别，是明确哪些内容可以决定标签、哪些内容能进入模型输入。[CARE 首错构造](https://arxiv.org/html/2611.02839v1#S6.SS1)、[E-GenRM 决策数据](https://arxiv.org/html/2611.03008v1#S4.SS1)

### 3. 运行系统：版本与验收是训练数据的一部分

NorthCUA 明确保留环境完整记录、模型实际可见上下文及异步片段的行为版本；CARE 再加上当时适用的 SOP 与故障归因。两者说明，训练样本应是有版本的执行记录，而不仅是一个问题、一个回答和一个标量奖励。[NorthCUA 分段策略](https://arxiv.org/html/2611.02102v2#A5.SS3)、[CARE 归因](https://arxiv.org/html/2611.02839v1#S5.SS2)

系统级收益也最难归因。NorthCUA 的多阶段成绩支持整条生产链可运行，未独立证明每个记忆或压缩模块的增益；CARE 跨轮同时维护 Harness，只有同期共享运行条件的比较能较好控制这些变化。完整成本还包括判题、历史采集、失败复核、恢复、教师调用和训练，不能只取某个学生更新阶段的 GPU 小时。

## 总结与启示

**最值得先做的是提高每条轨迹的可解释性。** 把模型当时的上下文、环境状态、动作、返回证据、版本及后续验收分开保存。这样既能重放，也能定位错误和生成不同训练视图。

**历史复用先从采样分配和可恢复进度做起。** SWE-Trail 的对照显示，多采成功轨迹与学生更会解题并不等价；SCOPE 和 TriGRPO 进一步展示了局部进展与分支可以怎样成为学习资源。选择机制时先确认环境是否支持真实恢复与一致验收。

**细粒度监督需要边界检查。** 决策级损失、步骤权重、首错修复和偏好奖励各自解决不同噪声，不能混成一种“更强 RL”。先用同模型、同任务和可比较预算测一个改动，同时保留失败与负结果，再扩大训练规模。
