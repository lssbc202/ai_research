### G-CAST：随工具和技能更新持续训练购物 Agent

> **原题** [G-CAST: Governed Continual Self-Training for E-Commerce Agents under Evolving Demands](https://arxiv.org/html/2611.17814v1) \
> **作者** Yuechun Yu、Wenzheng Kong、Xiaofeng Mao、Jin Zhang \
> **机构** Alibaba Group \
> **时间与版本** [v1 首次提交](https://arxiv.org/abs/2611.17814v1) 2026-11-13 14:53:56 北京时间。实读 [v1 HTML](https://arxiv.org/html/2611.17814v1)。

**研究问题**

工具、SKILL.md 和流程变动时，查询的最有效动作和评分标准会一起变。沿用旧奖励可能同时漏判新能力、掩盖老任务退步。

**研究方法**

每段以已经验收的检查点起步，在当前工具和技能版本上为每条查询采八次。全低分且有核验示范的进 SFT 池，成功失败混合的进 RL 池，全高分的保留作回归监测。池内再按高熵优先，给不确定查询更多预算。

SFT 和 RL 更新 Qwen3-4B-Thinking-2507。作者逐段修订可执行奖励，包括工具格式、结论有无证据支持、技能选择与遵循步骤。每段候选仍在同一个冻结评估奖励和所有已引入时期留出集上比较。 [方法原文](https://arxiv.org/html/2611.17814v1#S4)

**实际贡献**

工具、数据路由、奖励与检查点准入有共同版本边界。隔离训练奖励和固定评估，也让读者能比较改动前后的分数。

**结果与代价**

四个时期工具由 4 增至 23，每期先采 1.6 万条轨迹。末期累计奖励 0.8078，AutoTrainess 为 0.7911。定额消融中，奖励加熵的训练后得分 0.7930，奖励加随机是 0.7721。前两期总体不及 AutoTrainess，且评价来自单业务内部分数，不能当通用任务成功率。 [实验原文](https://arxiv.org/html/2611.17814v1#S5.T2)

**洞察评论**

给轨迹留 query、工具或技能版本、奖励版本及检查点四项标识。这样可以先查新版工具是否使旧评分失真，再决定更新奖励、训练数据或模型。

### LEAD-RL：搜索分工如何给子 Agent 分配信用

> **原题** [From Delegation to Coordination: Learning Efficient Multi-Agent Deep Research](https://arxiv.org/html/2611.17041v1) \
> **作者** Yuyang Wu、Yang Liu、Zequn Xie、Junjie Wang、Dan Yang、Zehao Tan、Ding-Chu Zhang、Junming Yang、Yue Shen、Jian Wang、Jinjie Gu \
> **机构** 原文未列 \
> **时间与版本** [v1 首次提交](https://arxiv.org/abs/2611.17041v1) 2026-11-13 00:26:27 北京时间。实读 [v1 HTML](https://arxiv.org/html/2611.17041v1)。

**研究问题**

主 Agent 负责分派和综合，子 Agent 负责查证。最终答案正确时，坏报告可能被主 Agent 纠正，若训练把团队得分平分给所有角色，就会同时强化坏报告。

**研究方法**

执行 Harness 允许主 Agent 搜索或并行委托，隔离子 Agent 的长搜索轨迹，只回传核验后的证据报告，最终答案另有核验。两个执行核验角色也调用共享策略。训练 Harness 保留各分支证据、委托要求和报告。

SFT 后对共享策略做样本级 GSPO，主 Agent 获得由最终正确性决定的团队优势。另一个仅训练时可见的裁判用参考答案和证据评子报告，有帮助的报告屏蔽负优势，有害的屏蔽正优势，中性保持原信号；每问采四条完整 rollout。 [方法原文](https://arxiv.org/html/2611.17041v1#S3.SS3)

**实际贡献**

联合训练既能让分派者适应子 Agent，也能让子 Agent 学报告证据。这里明确给出两个角色共享权重时，团队奖励如何进入各自的轨迹损失。

**结果与代价**

Ling-3-Flash 的 BrowseComp，贡献门控比两角色同奖从 71.00% 到 73.49%，关键路径步数由 323.30 到 244.22；SFT 是 72.50%。按关键路径计的效率不同于总 token 或实测延迟，Ling 配置的总 token 还由 330.7k 增至 336.9k，另有大模型裁判成本。 [实验原文](https://arxiv.org/html/2611.17041v1#S4.T3)

**洞察评论**

委托日志应含父任务、子任务要求、执行证据和被核验的报告。评信用时对照只训主 Agent、团队同奖和子报告门控，才知道收益来自分工、联合训练还是评分规则。

### AutoRL：用多 Agent 监控和干预实际 RL 训练

> **原题** [AutoRL: A Multi-Agent System towards Autonomous Reinforcement Learning](https://arxiv.org/html/2611.17790v1) \
> **作者** Simon Tang、Wenjie Shi、Yongjing Yin、Keheng Wang、Jialin Liu、Zheng Zhang、Linvo Lin、Xiangyuan Xue、Kan Ren、Jingang Wang、Xunliang Cai \
> **机构** Meituan、The Chinese University of Hong Kong、ShanghaiTech University、Fudan University \
> **时间与版本** [v1 首次提交](https://arxiv.org/abs/2611.17790v1) 2026-11-13 14:06:36 北京时间。实读 [v1 HTML](https://arxiv.org/html/2611.17790v1)。

**研究问题**

训练常因奖励实现、数值不稳或通信故障停住，日志本身不会告诉工程师何时应该继续、调参或回滚。有没有可审查的干预记录，决定这些试错能否复盘。

**研究方法**

四个观测角色分别看梯度、rollout、评测和效率，研究角色据证据提出候选修复。编排器决定执行、核对改动是否真正生效，必要时回到已保存检查点。共享记录包含诊断、候选、检查和干预结果。

Qwen3 实验从 GRPO 起跑，LongCat-Flash-Lite 编码 Agent 使用全异步 RL。系统实际改过评分实现、熵项、数据、裁剪范围和学习率。参数更新发生在被监督的目标模型，管理训练的 Agent 调用现有模型。 [方法原文](https://arxiv.org/html/2611.17790v1#S2.SS4)

**实际贡献**

论文把运行时事件、回滚和后续评测接到同一条记录上，展示监控 Agent 能完成哪些训练操作，以及哪些改动只能停在提案层。

**结果与代价**

同一 Qwen3-4B 初始配置下，AIME 2024 从静态 GRPO 的 46.67% 到 66.67%。14.7 天编码实验用 28×8 GPU，记录 11 次故障，SWE 相关 pass@1 从 52.29% 到峰值 65.13%，结束为 63.20%。编码长跑只有一条主要记录，其中一次修复还引入 dtype 故障。 [实验原文](https://arxiv.org/html/2611.17790v1#S3.SS5)

**洞察评论**

闭环所需的不是更长的诊断文本，而是可操作的证据接口：监控窗口、当前模型、采样版本、改动生效点和可恢复检查点。长跑结果适合评价接管和恢复能力，和受控算法比较应分开解读。

### TIDE：减少在策略训练中等待长轨迹的空转

> **原题** [TIDE: Reclaiming Lost Performance In On-Policy Reinforcement Learning](https://arxiv.org/html/2611.17924v1) \
> **作者** Mathew Jacob、Morgan Borjigin-Wang、Kan Zhu、Po Hao Chen、Yi Pan、Andy Ruan、Nayani Modugula、Ethan Lavi、Luis Ceze、Malte Schwarzkopf、Akshay Narayan、Deepti Raghavan、Stephanie Wang \
> **机构** University of Washington、Brown University、UC Berkeley、New York University \
> **时间与版本** [v1 首次提交](https://arxiv.org/abs/2611.17924v1) 2026-11-13 17:03:23 北京时间。实读 [v1 HTML](https://arxiv.org/html/2611.17924v1)。

**研究问题**

同步 RL 在较短轨迹结束后仍要等少量长轨迹。多轮 SQL 调用的长尾尤其明显，放大了推理显卡和训练显卡之间交接的闲置。

**研究方法**

路由根据各推理器剩余请求、目标 KV 缓存和训练并行度，合并尾部生成，把空出的 GPU 转给训练器。后者收到已完整的样本组就分批累积梯度。

同一步内所有轨迹仍由同一模型版本产生，梯度裁剪和优化器更新收齐后执行。Text2SQL 复用 SkyRL 训练配方，更新 Qwen2.5-Coder-7B-Instruct，实际执行一至五轮生成与 SQLite 请求。 [方法原文](https://arxiv.org/html/2611.17924v1#S4)

**实际贡献**

与一次切换半数 GPU 的 RollPacker 相比，分批迁移能根据负载调节。论文把调度改变和训练语义区分开，可单独核查吞吐来源。

**结果与代价**

Text2SQL 在 8×H200 和 4×L40S 上，端到端相对共置基线提速 1.36× 和 1.21×。单轮 DAPO-Math 分别为 1.16× 和 1.17×；测速只覆盖单节点、35 步 SQL 和 20 步数学训练，迁移效果受 KV 余量和卡间互联约束。 [实验原文](https://arxiv.org/html/2611.17924v1#S6.SS2)

**洞察评论**

先拆出每步的显卡空转、长轨迹等待、KV 迁移和重分片成本。TIDE 解决单位时长可执行的训练量，证据重点在吞吐。

### 用电池仿真反馈训练快充控制 Agent

> **原题** [Large Language Model-Empowered Intelligent Agent for Adaptive Fast-Charging Control of Lithium-Ion Batteries](https://arxiv.org/html/2611.18140v1) \
> **作者** Joey Chan、Haoyu Pan、Zhen Chen、ErShun Pan \
> **机构** Department of Industrial Engineering and Management, Shanghai Jiao tong University \
> **时间与版本** [v1 首次提交](https://arxiv.org/abs/2611.18140v1) 2026-11-13 21:11:04 北京时间。实读 [v1 HTML](https://arxiv.org/html/2611.18140v1)。

**研究问题**

固定电流规则容易部署，但不同电池参数、温度和老化状态使可接受的充电动作不断变化。让模型选动作需要可执行接口和统一安全约束。

**研究方法**

模型根据当前电池读数生成带电流、时长和截止条件的 JSON；确定性过滤器校验再送入 PyBaMM。32 种模型和参数组合产出 133,618 条专家标注用于动作 SFT。

在最多 1,024 个仿真电池状态提示上采多候选动作，各做单步仿真。GRPO 把荷电进展、温度、退化、时间、无效输出和过滤干预计入得分，更新 SFT 适配器。训练以单步反馈为主，评估验证多轮周期。 [方法原文](https://arxiv.org/html/2611.18140v1#S3)

**实际贡献**

程序可把结构化动作、执行结果和安全过滤归因到同一条训练样本，便于判断模型改善来自学会控制还是更多依赖保护逻辑。

**结果与代价**

八个仿真工况，至少一种偏好设置在等能量容量保持率上胜过最强非 LLM 基线五次、持平两次。非等温的 DFN/Chen2020 为 46.55%–46.73%，最强非 LLM 为 46.01%。同约束下仍有落后工况，实电池和更长周期未被验证。 [实验原文](https://arxiv.org/html/2611.18140v1#S4)

**洞察评论**

迁移到其他可验证工具任务时，可分别记录模型原动作、过滤后的实际动作、以及被修改的原因；否则过高成功率可能只是硬约束替策略纠错。

## 领域结构与研究进展

### 生产 Harness 的版本与数据回流
G-CAST 里的工具升级改变了可做的动作，也改变了什么样的结果算合格。以当前 Harness 重放可修正候选数据分布；同一份冻结评估能比较新旧检查点。快充 Agent 则把格式、模拟成效和安全干预拆开记录，说明动作有没有被执行需要和它得了多少分一起追踪。
### 委托与信用分配
LEAD-RL 把任务成功给主 Agent，把子报告对成功失败的贡献作为子轨迹的更新开关。同样是子 Agent 提交报告，角色与执行证据可以使同一条团队奖励进入不同的损失；缺这份关系时，最容易奖励被主 Agent 成功纠正的错误。
### 训练稳定性与吞吐
AutoRL 的控制点是发现异常后改配方并恢复，TIDE 的控制点是让同版本 rollout 的梯度计算更早开始。前者应审计改动、回滚与恢复质量，后者应在相同训练语义和预算下对比 GPU 等待。把两者分开记账，可以确认究竟是每步更快，还是故障处理后有效步数更长。

## 总结与启示

优先读 G-CAST。工具、奖励、数据与权重都在变化时，可用固定留出评估比较旧新检查点，再用单独的日志检查奖励迁移和工具回放是否按预期工作。涉及并行委托时，LEAD-RL 的同奖对照可直接检验子轨迹信用是否改善。
