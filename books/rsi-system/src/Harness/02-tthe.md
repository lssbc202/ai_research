# TTHE

**论文**：Jun Nie 等，《TTHE: Test-Time Harness Evolution》，arXiv:2607.08124v1，2026 年 7 月 9 日。  
**原文**：[arXiv HTML](https://arxiv.org/html/2607.08124v1)

## 核心判断

TTHE 研究一个具体问题：当任务标准答案对智能体不可见时，能否根据当前测试任务的执行轨迹，修改控制智能体工作的程序，并提高任务正确率？论文把这个程序称为 *harness*：它负责组织上下文、调用模型和工具、检查结果、处理失败。TTHE 保持底层模型权重不变，在每批测试任务上生成多个 harness 候选，根据运行证据选出一个，并将选中的程序带到下一批。

在作者选定的困难任务子集上，这套流程优于固定的基线 harness。最有价值的发现还包括它的失败模式：正确候选有时已经生成，评判器却因执行证据不可靠而选错。论文主要证明了**适应当前批次后的收益**；对尚未参与适应的新任务是否同样有效，仍需进一步评测。

## 研究问题与已有工作的关系

模型只是智能体系统的一部分。同一个模型置于不同的 harness 中，可以采用不同的检索、验证和恢复流程，产生不同的结果。许多自动优化方法也会读取失败记录、修改提示词或源代码，再运行候选。TTHE 沿用这一基本框架，将选择条件设为：改进器能看到当前任务的输入和执行轨迹，但看不到任务级标准答案、参考输出或隐藏测试结果。

这里的“测试时”指适应发生在处理目标测试任务的过程中。它不表示测试集不存在，也不表示最后没有标准评分。它还不表示在单个任务执行到一半时热替换程序：论文以**批次**为单位，运行候选、修改程序、重新运行这批任务，然后提交一个版本。

几篇相邻工作的差别有助于定位这篇论文：

| 工作 | 主要改进对象与依据 | 与 TTHE 的关键关系 |
|---|---|---|
| [Darwin Gödel Machine](https://arxiv.org/html/2505.22954v1) | 修改编码智能体自身代码，借编程基准成绩评价候选，并维护候选档案 | 代码自改写与多路径搜索已有先例；DGM 强调改进后的编码能力还能用于下一轮自我修改 |
| [Meta-Harness](https://arxiv.org/html/2603.28052v1) | 编码智能体读取历史 harness 的代码、轨迹和评测分数，搜索新的 harness | 与 TTHE 的程序搜索方式最接近；可见的评测分数使候选选择条件不同 |
| [EvoTest](https://arxiv.org/abs/2510.13220) | 每回合后分析游戏轨迹，调整提示词、记忆、超参数与工具使用配置 | 表明“执行中持续适应”并非 TTHE 独有；TTHE 将修改对象扩展为可执行 harness 代码 |

因此，论文的新意主要落在**无任务级金标准反馈、当前测试批次上的程序修改与选择**，并分析代理信号和评判器的可靠性。它没有证明改进器本身也在不断变强，因此不宜把结果直接解释为改进速度会持续加快的递归自我改进。

## 方法：一批任务如何产生下一版 Harness

设 (M) 为冻结的模型，(H_t) 为第 (t) 批开始时已提交的 harness，(X_t) 为当前无标签任务批次。一次运行会产生输出和执行轨迹；轨迹包含模型提示与回复、工具调用与结果、运行错误、中间产物等。作者希望提高的真实指标是任务正确率，但该指标需要标准答案，不能直接用于改进循环。

论文的算法可以按以下顺序阅读：

1. **观察**：运行 (H_t) 处理整批 (X_t)，缓存输出并记录轨迹。
2. **分支修改**：从 (H_t) 建立 (G) 条分支。每条分支的提案器阅读执行证据，修改自己分支的父版本；它可以借鉴其他分支的代码和轨迹。无效或无法加载的新版本退回父版本。
3. **重新观察**：运行各条分支的新版本，重复修改与执行，共进行 (R) 轮。实验中的分支被引导向保守修复、探索和对抗性检查等不同方向。
4. **提交**：评判器检查最后一轮的候选代码、轨迹和代理信号，必要时补做探测或重新执行，选出一个 (H_{t+1})。它成为下一批任务的起点。
5. **事后计分**：使用选中版本在当前批次运行时缓存的输出，与标准答案或隐藏测试比较。这个分数只用于研究报告，不反馈给提案器和评判器。

演化的实体是 harness 源码，实现中通常是 Python 类。修改可以涉及上下文构造、工具调用顺序、确定性检查、条件重试与错误恢复。它不是模型权重更新，也不限于改写提示词。

### 无标准答案时使用的证据

| 信号 | 具体含义 | 局限 |
|---|---|---|
| 执行健康 | 输出可运行、格式正确、形状与任务相符 | 正常执行的 SQL 仍可能答错问题 |
| 往返一致性 | 把输出反推成描述，检查是否仍符合原任务 | 语义近似不能代替标准答案 |
| 公开测试通过率 | 使用任务公开的样例或仓库测试 | 通过公开测试仍可能失败于隐藏测试 |

原始轨迹和这些信号会一起交给提案器与评判器，而不是合成一个固定权重的总分。“无标签”在本文中的范围是：**任务级金标准不进入改进循环**；公开测试和执行反馈仍然可用。

### 改进器使用的模型

主实验中，求解器、提案器和评判器调用同一个冻结的 **DeepSeek V4 Flash**。求解器运行在被演化的任务 harness 中；提案器和评判器运行在提供读文件、改代码、执行和探测工具的 Claude Code 编码智能体框架中。论文说明，Claude Code 在此充当操作界面，其中的模型调用仍路由到同一个底层模型。BIRD 的补充实验还分别使用 MiMo V2.5 和 Kimi K2.5，同时承担求解与改进角色。

## 实验结果与可支持的结论

作者在运行前固定各任务子集，用固定基线 harness 对比完整的 TTHE 流程。SQL 以执行结果集是否匹配金标准计分；代码任务以是否通过全部隐藏测试计分。SWE-bench 从现成的 mini-swe-agent 开始演化，其余主要任务采用 ReAct 式基线。

| 困难任务子集 | 题数 | 固定基线 | TTHE | 提升 |
|---|---:|---:|---:|---:|
| BIRD，文本生成 SQL | 50 | 12.0% | 50.0% | 38.0 个百分点 |
| LiveCodeBench，竞赛编程 | 60 | 30.0% | 38.3% | 8.3 个百分点 |
| SWE-bench Verified，软件修复 | 40 | 20.0% | 35.0% | 15.0 个百分点 |
| DS-1000，数据科学代码 | 50 | 38.0% | 44.0% | 6.0 个百分点 |

BIRD 的 50 题来自基线反复失败的题目，因此 12% 的低起点由选题方式部分决定。38 点提升说明系统挽回了不少此类失败；它不能当作完整 BIRD 基准上的一般增益。不同任务的筛题方法、基线与评分标准也不相同，表中的提升幅度不构成严格的跨任务比较。

在独立的办公工具任务 claw-eval 中，30 个任务上的平均分由 **48.9% 提高到 69.8%**，其中 28 个任务有所改善。该指标是分级评分，与上表的二元正确率不同。附录说明，这 30 个任务从基线分数低于 0.60 的任务中筛出，六批任务还按基线难度排序。claw-eval 的事后测量使用独立评分模型；评分器在改进循环中关闭，评分目标和分数不提供给提案器或评判器。

演化出的代码提供了可检查的行为证据。例如，SQL harness 增加查库核对筛选值、检查结果列数和按具体错误重试；软件修复 harness 增加先复现问题、定位根因、修复后验证，以及首次运行产生空补丁时的恢复分支。这些都是作用于后续任务的控制规则。

## 消融实验与失败诊断

搜索预算的作用并不单调。在 BIRD 子集上，单分支从 1 轮增至 3 轮，正确率由 46% 降到 40%；三分支从 1 轮增至 3 轮，则由 44% 升到 50%。三分支还采用不同的角色提示，因此该结果不能单独证明“增加分支数量”带来了提升。批次大小也存在折中：所测设置中，每批 10 题达到 50%，5、25、50 题分别为 44%、38%、44%。这些消融均是单次完整运行，需要多随机种子检验稳定性。

跨批次保留选中的 harness，得到 50% 的整体正确率；每批从基线重新开始，得到 44%。这说明已积累的程序结构能提供有用起点。但两种方案都先适应当前批次、再对当前批次计分，因此 6 点差异仍不能直接证明未来新任务上的泛化。

最关键的诊断是候选生成与候选选择各有瓶颈。实际选中版本的 BIRD 正确率为 **50%**；事后利用金标准，在评判器所见候选中做理想选择，可达 **64%**。把整个搜索过程中生成的候选都纳入事后分析，上界为 **70%**。前一段差距说明评判器漏选了有用候选，后一段差距说明搜索本身也没有覆盖部分题目。论文举出的失误包括：SQL 全部正常执行，但被选版本返回了多余列或错误的聚合粒度。

## 证据边界与下一步实验

**当前批次适应。** 主实验在同一批任务上收集无标签证据、选择 harness，并用该批任务计分。这是传导式测试时适应的有效评测协议，支持“接触当前任务后有所改进”。要检验前向泛化，应让第 (t) 批选中的程序先处理未参与适应的第 (t+1) 批，在其继续适应前计分，并改变任务批次顺序做重复实验。

**计算预算。** 主对照是固定基线，TTHE 为生成、运行、探测多个候选付出了额外计算。论文尚未给出与同预算的多次尝试、候选答案选择或开发阶段程序优化的充分比较。因此，现有结果建立了完整流程的收益，尚不足以量化其相对这些替代方案的独特优势。

**评判器依据。** 作者提出原始轨迹对发现控制策略很重要，但还没有系统地只给分数、给分数与摘要、给完整轨迹做信息消融。评判器实际存在显著的选择失误，代理信号质量是本方法的核心瓶颈。

**运行环境。** 实验使用受限沙箱。提案器可改写可执行程序；若部署到开放工具环境，需要针对程序权限、资源消耗和错误行为另行设计约束。

## 阅读结论

TTHE 的技术价值在于，把“缺少任务级正确性反馈时如何改写并选择 harness”明确为一个可实验的问题，并用跨任务的结果和事后诊断展示了收益及选择失误。读取轨迹、让模型改代码和并行搜索都已有先例；这篇论文的贡献集中在它们于**无金标准的测试批次**中的组合与评测。它展示了程序能够持续更新，但尚未证明改进器自身递归增强，也未证明这些更新对未来未见任务稳定有效。
