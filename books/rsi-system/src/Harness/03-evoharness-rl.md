# EvoHarness-RL

> **论文**：Xuying Ning 等，*EvoHarness-RL: Learning Self-Evolving Runtime Harness for Long-Horizon LLM Agents*，arXiv:2608.05446v1，2026 年 8 月 5 日。  
> **原文**：[arXiv HTML](https://arxiv.org/html/2608.05446v1)  
> **阅读日期**：2026 年 10 月 9 日

## 一、核心结论

这篇论文研究的不是如何让模型自动编写或修改 harness 代码，而是**如何训练智能体在执行长任务时，有选择地使用外部状态**。作者设计了一个由 Belief、Progress、Experience 组成的 BPE harness，先用成功示范教 Qwen3-8B 理解这套接口，再用 GRPO 强化学习优化调用时机。与此同时，跨任务经验库根据轨迹和笔记不断整理。

在 ALFWorld 文本家务任务中，论文报告完整方法在已见任务上的平均成功率为 **96.9%**，在未见任务上为 **86.6%**。这个结果支持“训练模型与 harness 协调”在该环境中的价值；它尚不能证明同样的收益会直接迁移到网页操作或软件工程任务。

## 二、研究问题与定位

多步骤任务要求智能体持续记住环境状态、已完成的子目标，并复用此前的经验。论文将提示、工具、记忆、状态跟踪和执行反馈等运行时支持统称为 **harness**。传统做法往往由开发者规定何时查询记忆、何时记录进度；作者希望把这些选择变成模型可学习的动作。

论文的两个具体问题是：如何从交互轨迹形成有用的外部状态；以及外部状态的读取、写入都会消耗交互步数时，模型如何判断一次 harness 调用是否值得。EvoHarness-RL 的研究重点因此是 **harness 使用策略学习**。ALFWorld 适配器和内部存储由作者针对任务实现，并非直接拿一个现成开源 harness 当实验对象。

## 三、方法：BPE 接口和四种动作

| 外部状态 | 在 ALFWorld 中保存的内容 | 对应动作 |
|---|---|---|
| **Belief**：当前环境估计 | 物体状态、位置和关系；根据动作与观察更新 | `track[object]` 查询物体，或 `track[world]` 查询简要全局状态 |
| **Progress**：执行进度 | 有容量限制的子目标与状态记录 | `commit[subgoal]` 记录当前子目标 |
| **Experience**：跨任务经验 | 通用技巧、任务步骤、常见错误、物品位置线索 | `recall[query]` 检索；`note[insight]` 留下新发现 |

模型每一步从**环境动作**和上述 **harness 动作**中选一个。harness 动作也占一步预算，因此多调用不必然更好。这里的 BPE 是面向模型的功能接口；换一个任务领域，仍需实现该领域的状态跟踪、动作分发与经验存储。

在论文的具体实现中，Belief 由规则解析器维护，Progress 是有界子目标列表，Experience 以关键词匹配检索，并用访问次数支持低频条目淘汰。`note` 先写入临时缓冲区，不会即时改写主经验库；训练轮次结束时，外部整合模型才根据笔记和轨迹决定新增、更新、删除或跳过经验条目。

## 四、训练流程与“并行多路径”

**第一阶段：监督微调（SFT）。** 作者让 Claude Opus 使用同一 BPE 接口完成训练任务，只保留成功轨迹作为示范。论文从 500 个训练游戏中得到 87 条成功轨迹、1,153 个下一动作训练样本，用来教 Qwen3-8B 执行环境动作并理解 `track`、`commit`、`recall`、`note`。

**第二阶段：成本感知 GRPO。** 从 SFT 检查点出发，对同一提示采样多条任务轨迹；实验设置为每组 8 条。轨迹奖励以任务完成为主：完成任务获得 10 分，成功轨迹还有步数效率奖励；训练初期有逐渐衰减的动作多样性奖励，重复或无效动作受到惩罚。GRPO 比较组内轨迹奖励，更新同一个 Qwen3-8B 策略模型。

这里的“多路径”指**并行采样不同执行轨迹**，不是让多个 harness 代码版本并行进化。采集一批轨迹时主经验库保持固定，轨迹产生的笔记和总结暂存；到轮次边界才统一整合。论文也没有名为 *improver* 的独立模块：模型参数由 SFT/GRPO 更新，经验条目由整合模型维护，两者作用不同。

## 五、实验结果与证据范围

作者在 ALFWorld 的六类任务上评估：取放、在灯光下查看、清洁后放置、加热后放置、冷却后放置，以及放置两个物品。表中的数值为论文报告的平均任务成功率。

| Qwen3-8B 方法 | 已见任务 | 未见任务 |
|---|---:|---:|
| ReAct 基线 | 47.9% | 50.0% |
| EvoHarness-Base：只加推理时 BPE | 56.4% | 77.6% |
| EvoHarness-SFT | 68.6% | 69.4% |
| EvoHarness-RL：SFT 后再做 GRPO | **96.9%** | **86.6%** |

已见任务包含 140 个验证任务。完整方法比同表中的普通 GRPO（65.6%）高；冻结的强模型加入推理时 BPE 也有收益，例如 GPT-5 从 60.7% 到 85.0%。这两组结果分别说明：BPE 接口本身可以提供帮助，而专门训练模型的调用策略可能带来更大收益。未见任务上 SFT 的 69.4% 低于只加 BPE 的 77.6%，说明模仿成功示范本身并不能保证调用策略适应新任务；作者认为 GRPO 重新校准了调用成本。

论文还做了组件消融。下表的消融**只针对冻结 Qwen3-8B 的推理时 BPE 版本**，不是从训练后的 96.9% 模型中移除组件。

| 推理时 BPE 配置 | 已见任务平均成功率 |
|---|---:|
| 完整 BPE | 56.4% |
| 去掉 Belief | 50.0% |
| 去掉 Progress | 50.7% |
| 去掉 Experience | 48.6% |

三个组件被移除后都出现平均下降。Experience 的平均降幅最大，但这不能直接量化它在**训练后**策略中的独立贡献。

## 六、训练中观察到的两种变化

**模型侧：harness annealing。** SFT 初始策略频繁调用 BPE；GRPO 训练后，调用下降并稳定在每个任务约一次，同时成功率继续提高。附录显示 `recall` 保留得最久，`commit` 和 `note` 下降较快。作者将其解释为模型学会了常见任务做法，只在外部经验仍有价值时访问 harness。“内化”是对行为曲线的解释，并非对模型内部知识的直接测量。

**状态侧：harness evolution。** Belief 和 Progress 主要在单次任务内变化；跨任务的 Experience 则先扩张，随后通过整合重复技巧、修正过时线索和淘汰少用条目趋于稳定。附录中的水壶案例展示了这一意图：旧经验提示水壶在台面，智能体最终在炉灶找到它，随后留下纠错笔记；主经验库要等后续整合才可能更新。

## 七、评价与局限

**主要贡献**是把外部状态抽象为统一接口，并将“何时使用外部状态”纳入模型训练目标。论文同时展示了模型策略与经验库内容在不同时间尺度上的变化，比单纯增大记忆库更关注使用成本。

解读结果时有四个边界。第一，已见和未见结果都来自 ALFWorld，未见任务仍属于同一环境及六类任务，不等于跨领域迁移。第二，组件消融发生在冻结模型上，无法直接拆分完整 RL 方法中各组件的贡献。第三，论文展示了经验库演化，但未单独给出“停止整合经验库、保持其他训练条件相同”的主实验对照，因此不能从现有表格精确归因经验整理本身带来的增益。第四，成本感知奖励主要用交互步数表示成本；系统还依赖 Claude Opus 生成示范并在训练轮次之间整合经验，不能把它理解为完全由 Qwen3-8B 自主完成的闭环。

## 八、最终理解

EvoHarness-RL 可以概括为：**人工实现一个稳定的 BPE harness → 用成功轨迹教模型使用接口 → 用 GRPO 学习何时值得调用 → 在轮次间整理跨任务经验。** 演化对象是模型的调用策略和经验库内容，**不是 harness 源代码**。论文在 ALFWorld 上提供了有力的性能证据；将该思路移植到其他领域时，仍需重新设计适配器，并验证奖励、调用成本与经验整理机制是否有效。
